# UI редактора: уточнение визуальной иерархии

[English](../editor-ui-hierarchy.md) | [Русский](editor-ui-hierarchy.md) | [Документация](README.md)

**Дизайн-предложение от 14 ноября 2026.** Уточнение меняет макеты документации
Engine Overview (P01), Inspector (P08) и Assets (P09), требования к их состояниям
и добавляет по варианту узкой области. Оно не меняет нативный редактор, команды,
форматы проектов, права или сохранённые раскладки. Остальные компоновки каталога
сохраняют прежний дизайн; полнота каталога не доказывает одинаковое удобство всех
его компоновок.

## Проблема и порядок чтения

В прежних макетах навигация, значения свойств, диагностические факты и действия
имели похожие контейнеры и визуальный вес. Короткие факты занимали строки высотой
72–88 точек; вложенные обводки и повторные разделители определяли группировку.
Выбор в Overview мог обозначаться словом `Selected` без заметной выбранной
строки. Проверки исходников, ссылок и контраста не доказывали удобный порядок
чтения.

Уточнённый порядок: **текущий контекст → выбранный предмет → задача и основное
действие → подтверждающие сведения**. Происхождение объекта/компонента и состояние
черновика видны там, где влияют на решение. Unknown, отсутствующие данные,
отклонения и ограничения доступа не должны исчезать в свёрнутых технических
подробностях.

## Общие отступы и акценты

Размеры заданы в логических точках egui по [технической базе](editor-ui-spec.md).
Группа `hierarchy` в [токенах](../editor-ui-tokens.json) относится к этим трём
прототипам. Это не глобальная тема runtime и не перевод всех 72 элементов на
новый дизайн.

| Роль | Геометрия и оформление |
| --- | --- |
| Связанные элементы | Интервал 4–8 внутри группы; не разделять линией каждый факт только для чтения. |
| Разные группы | Интервал 24; 32 между крупными разделами. Заголовок раздела держится рядом с содержимым. |
| Строки навигации / подсистем | Высота 40 / 56. Двухстрочная подсистема содержит имя и короткое назначение. |
| Строки фактов / полей | Высота 28 / 36; сами редактируемые элементы остаются высотой 28. Многострочные значения растут вместо обрезки. |
| Форма Inspector | Ширина подписи 112; содержимое не шире 720. Три поля вектора остаются в одной строке; широкая область не растягивает значения на всё окно. |
| Иерархия текста | Выбранный предмет — 20 semibold, раздел — 16 semibold, обычный текст — 14, метаданные — 12. Заголовок области и предмета имеют разный смысл. |
| Основное действие | Не более одной контекстной кнопки со сплошным `accent` и текстом `on_accent`. Подробностям только для чтения не нужно выдуманное основное действие. Вторичные переходы — текст/иконка; разрушительные команды файлов/компонентов отдельно. |
| Выбор | Фон выбора плюс маркер/галочка и имя предмета; не только цвет. Фокус клавиатуры остаётся отдельной обводкой по общей базе. |
| Границы | Сохранить значимые границы полей и разделители областей. Для групп использовать заголовки/отступы вместо вложенных карточек вокруг всех фактов. |
| Поверхности | Спокойный canvas для навигации/preview, panel для содержимого, raised для каркаса/временных поверхностей. Палитра и требования контраста не меняются. |

Дополнительные SVG — **варианты dock-области шириной 480 точек**, а не уменьшенные
экраны 1280 точек и не целые окна ОС. Они сохраняют текст 14/12 и настоящие размеры
элементов. Будущая нативная реализация также должна учитывать рабочую область
монитора, длинные значения/прокрутку и отдельно проверять фокус/DPI/доступность.

## Engine Overview — P01

[Основной макет](../media/editor-ui-catalog/p01.svg) · [Узкая область](../media/editor-ui-catalog/p01-compact.svg) · [Состояния](../media/editor-ui-catalog/p01-states.svg)

Три визуальных уровня разделяют группы состава (ширина 184), список подсистем
(280) и выбранные подробности с интервалами 24. `Technical Engine` имеет маркер
группы; `Rendering` — постоянную выделенную строку/галочку. Подробности сначала
объясняют назначение и текущую реализацию, затем дают основной путь
`Open render graph` и вторичный переход `Show renderer node`. Оба соответствуют
существующим поддержанным целям; нового выбора архитектуры или неявной активации
модуля здесь нет.

`Installed`, `Offered`, `Participating` остаются тремя независимыми подписанными
фактами. Обычные значения примера не становятся зелёным значком `Ready`.
Ограничение сведений о готовности runtime остаётся видимым. Только дополнительные
сведения об источнике могут сворачиваться в `Source details`; ошибки и причины
недоступности действий остаются снаружи. Область 480 точек показывает выбранные
подробности с `Back to composition`, сохраняя список/поиск/выбор при возврате.

## Inspector — P08

[Основной макет](../media/editor-ui-catalog/p08.svg) · [Узкая область](../media/editor-ui-catalog/p08-compact.svg) · [Состояния](../media/editor-ui-catalog/p08-states.svg)

Идентичность объекта и контекст prefab ведут к Transform, затем к отдельным
разделам Actor и Health своих источников. Числовые поля выровнены; подписи рядом
со значениями. Меню компонентов содержат существующие действия компонента,
включая `Inherit defaults` или `Remove component`, где они поддержаны,
`Add component` остаётся вторичной командой документа. Вспомогательный контекст
широкого вида не конкурирует с колонкой полей и отсутствует в узкой области.

У скорости Actor в примере **локальный черновик 6.5**, отдельно от **авторского
переопределения 6.0**. `Apply Actor fields` означает существующий Apply конкретного
компонента; он не объединяет Transform, Health или другие черновики в новую
транзакцию. Жесты Transform сохраняют текущий Undo. Происхождение prefab/Health
отличает наследование от локального переопределения, не превращая defaults в
авторские значения. Пустой Apply сохраняет наследование. Стабильные ID только
для чтения; оформление не меняет владение `ComponentSchema`/`PropertySchema`,
точные ключи, неизвестные данные или разделение авторской сцены/Play.

**Ограничение черновиков Inspector до 2A:** [inspector_ui](../../crates/editor/src/game_ui.rs)
после Apply компонента задавал `field_key = None`; следующий проход пересоздавал
весь `component_drafts` из разрешённых значений компонентов. Несовпадение выбора
также вело по этому пути. Авторские значения других компонентов сохранялись,
но их неприменённые черновики прежние guards не защищали. Макет показывает
только один ожидающий черновик Actor. [Реализация этапа 2A](editor-ui-rollout.md)
теперь вводит сохранение черновиков по объектам, явные конфликты/отмену и
защищённые переходы; тесты с вводом мыши проверяют Apply компонента и смену
выбора. Полная нативная приёмка, ошибки и DPI всего этапа проверяются отдельно.

## Assets — P09

[Основной макет](../media/editor-ui-catalog/p09.svg) · [Узкая область](../media/editor-ui-catalog/p09-compact.svg) · [Состояния](../media/editor-ui-catalog/p09-states.svg)

Порядок чтения: папка/расположение, результаты в своей области, выбранный ассет.
Спокойное дерево использует узнаваемые иконки папок и вложенность; иконки типов
различают модели, текстуры, звук и прочие файлы. Выбор папки имеет маркер, ассета —
обводку/галочку. Показанные восемь элементов — данные примера, не сканирование или
изменение пользовательского проекта.
Поиск сохраняет прежнюю рекурсивную область; `Search folder and subfolders`
указывает её явно. URI вида `asset://a-hero` подписан `Asset reference`, отдельно
от ID манифеста `a-hero` без префикса.

Breadcrumbs находятся рядом с контекстом поиска/результатов. `Show address`
открывает выделяемый текст того же пути относительно проекта только для чтения,
не второй редактируемый источник навигации. Узкие подробности показывают этот
вариант адреса и `Back to models`; возврат сохраняет расположение, поиск и
стабильный выбор ассета. В прежнем предложении адреса `Copy absolute path`
остаётся в опциях расположения; это не второе значение адреса и не утверждение,
что этот предлагаемый элемент уже реализован в нынешнем редакторе.

`Import…` — основная команда папки. Подробности ассета используют ограниченное
preview, имя, путь и стабильную ссылку; `Usages…` и `Asset actions…` вторичны.
Rename/Move/Trash — явные команды выбранного стабильного ID, не побочные эффекты
нажатия плитки. Их предварительное сохранение, проверка ссылок, защищённые пути,
транзакции, восстановление и Undo сохраняются. Векторное preview модели условное;
оно не означает декодированную живую модель.

## Поддержка и проверка

Канонические требования: [данные каталога](../ui-catalog/catalog.json). Рендеринг:
[генератор](../ui-catalog/generate.py) и [уточнённые компоновки](../ui-catalog/hierarchy.py).
Пересоздание либо сравнение без записи:

```text
python -B docs/ui-catalog/generate.py
python -B docs/ui-catalog/generate.py --check
```

[Атлас](../media/editor-ui-catalog/index.html) показывает `Compact area` только
для P01/P08/P09 и возвращается к Layout при переходе к другому элементу.
В каталоге остаются 72 записи и 144 основных листа/листа состояний, плюс три узких
варианта. Полные английские/русские требования остаются согласованными.

Приёмка требует визуального осмотра всех шести изменённых основных/узких макетов,
трёх изменённых листов состояний, контраста выбора/основного действия/полей и
настоящей геометрии текста/элементов. Проверить генерацию, ссылки на исходники,
ссылки документов, выбор/клавиатуру/возврат из compact в атласе, узкую ширину
viewer и точное сохранение всех посторонних исходников/данных пользователя.
Независимое ревью должно оценивать порядок чтения и понятность задач вместе с
механическими проверками. Доказательства/привязка к исходникам находятся в
`outputs/reviews/editor-ui-hierarchy-20261114/`. Статическая/браузерная проверка
не подтверждает нативные команды, пользовательское тестирование удобства,
DPI/доступность, сохранение или производительность runtime.
