**Инженерный отчёт, 15 ноября 2026 года: ограниченные проверки, настоящие пути UI Full/Team и перенесённые Player из Full/Team пройдены.** Привязки исходников/артефактов и отдельное независимое заключение приведены ниже. Здесь записана работа по задачам ясности редактора 3.1–3.6. Это не означает безусловной приёмки выпуска или подтверждённого удобства для пользователей.

## Объём и полученное поведение

Для Team сохранён обычный путь **Tools → Project Settings**. Для Full с проверенными совместимыми исходниками сохранён путь **Windows → Composition → Engine Overview → подключённый рендерер → Open render graph**. Личные сохранённые раскладки и граница прав Full/Team/исходников сохранены. Открытие инструментов не меняет проект и не включает отсутствующий модуль.

Новая общая сводка объясняет AA и AO, называет подключённый рендерер, отличает отсутствующие встроенные проходы FXAA/SSAO от присутствующих, но отключённых, и разделяет настройку графа **Base pass enabled** и авторские команды Project. Доступные настройки определяются по настоящим целям команд; поддерживаются произвольные ID настроек и авторские подписи вариантов. Показанный результат явно является опорным расчётом: для игровых проектов используется нулевое время; текущее время Game и разрешённые команды рендеринга при выполнении могут давать другое состояние.

Выбор Project использует существующее немедленное принятие авторской настройки. Подготовка графики Game/Scene и принятое изображение отделены от этого действия и от сохранения. Графика может обновляться при приостановленном Play; для изменений графа исполнения сохраняется существующее требование Stop. Обратная связь показывает настоящую подготовку/ошибку, сохранение последней работающей версии при её наличии и необходимость проверить изображение. Сохранение, черновики и экспорт явно различаются. Повторно используются существующие удаление прохода, обходные соединения, очистка настроек и атомарные Undo/Redo; новое размещение использует начальные значения и не обещает восстановить пользовательские значения.

Изменение добавляет объяснения интерфейса, поиск пути, узкие тесты и безопасный отдельный пример «Contrasting edges» с диагностикой кадров. Алгоритм рендеринга, поведение runtime, зависимости и формат проекта не изменены. Для немедленного выбора не добавлена кнопка Apply, права Team не ослаблены, личные проекты/раскладки не заменены, этапы 0.5/G2 не реализованы. Версия бинарного файла/пакета остаётся 0.4.0; повышение версии не является доказательством завершения.

Full прошёл обычный запуск, сохранил первоначальную индексацию Assets, затем Engine workspace → Overview → Open render graph `Root/renderer` → F на сфокусированном canvas для вписывания и закрылся чисто. Полученный Player был запущен обычным способом и вернул заголовок окна «Contrasting edges», но срок одобрения Computer Use истёк до снимка. Сессия сброшена; завершён только принадлежащий проверке процесс Player после проверки пути исполняемого файла и диагностического state root. Код завершения общего скрипта `-1` отражает это прерывание, а не подтверждённое падение продукта. Для этой попытки не заявлены снимок или визуальный осмотр человеком.

Дополнительная существующая диагностика Player `--benchmark` завершилась автоматически с кодом 0: [нативный отчёт](../../outputs/release-041/player-window-diagnostic/native-frame-report.json), [сводка](../../outputs/release-041/player-window-summary.json). Это функциональное доказательство нативного окна без снимка. `target_met:false` сохранено: в нейтральном примере ноль врагов, и он не создаёт обязательную ARPG-нагрузку с 20 врагами. ## Ограничения и приёмка

Владелец и независимый автор ещё не прошли карточку. Время поиска настройки, активного редактирования, ожидания, помощь наблюдателя и субъективная видимость изменения краёв остаются неизмеренными. Автоматические тесты и исполнитель не заменяют этих участников.

Физические DPI/разные мониторы, аппаратный Linux, переносимость на чистой машине/холодный запуск и новые бюджеты FPS/производительности здесь не сертифицированы. Эта работа не подтверждает ARPG 60 FPS или более широкую приёмку G1/G2. Ограниченный инженерный успех обязан сохранять эти границы; для окончательного инженерного заключения нужны итоговая привязка исходников и независимое ревью, а удобство для пользователей остаётся отдельной непроверенной частью.
