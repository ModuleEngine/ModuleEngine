# Сведения о возможностях из исходных реестров

[English](../engine-capabilities.md) | [Русский](engine-capabilities.md) | [Документация](README.md)

Это основа данных этапа 1 [плана понятного редактора](editor-clarity-plan.md#stage-1).
Список описывает установленные возможности и авторское участие. Это не загрузчик
модулей, новый исполнитель или отчёт о запущенных/готовых экземплярах.
[Engine Overview](engine-overview.md) использует эти данные для обзора без изменения
документа и переходов к инструментам. Статус проверок и независимого ревью записан
в [текущем состоянии](current-status.md).

## Принадлежность и виды

`CapabilityMetadata` — исходные метаданные владельца, не авторские данные:
понятные `label`, `purpose`, смысловой `owner`, вид `kind`, `source_package`,
подсказки перехода к настройке и необязательные ссылки на библиотеки. Они
регистрируются рядом с существующими контрактами; поля не добавляются в
`GraphDocument`, `ModuleDescriptor`, `SystemDescriptor`, схемы компонентов или
содержимое точных lock.

| Владелец | Значение и нынешние примеры |
| --- | --- |
| `engine` | Техническая инфраструктура: хранение мира, извлечение сцены, software/Vulkan рендер, scalar/Custom hosts, сервисы звука/хранилища и общие библиотеки сетки, истории и действий. |
| `gameplay` | Переиспользуемые игровые механизмы: правила ARPG для движения/боя/здоровья/ИИ/событий и библиотека прохождения кампании. ARPG collision — игровой обработчик препятствий, а не общий физический сервис. |
| `project` | Правила и инструменты конкретной игры/примера: Crate Garden, исходная Puzzle с лимитом ходов, пример вращения и прежние данные движения. |
| `unknown` | Исходный пакет не объявил принадлежность. Пространства имён, имена crate и нативные features не используются для догадок. |

Вид отличается от владельца: исходный контракт, хранение мира, рендер, проход
рендера, исполняемая система, данные компонента, вклад в host, библиотека, сервис
или инструмент редактора. Библиотека не устанавливается фиктивной исполняемой
системой или узлом графа. Вклад в host описывает зарегистрированные обработчики
камеры/ввода/сцены/событий/сервисов; наличие не подразумевает компиляцию
необязательных UI callbacks.

## Фактический список и источники настройки

| Нынешние возможности | Источник и подсказки настройки |
| --- | --- |
| `world.ecs`, `world.objects`, `scene.extract` | Фабрики/контракты Core `ModuleRegistry` и исходные метаданные; корневой граф. Игровой маршрут по-прежнему владеет каноническим ECS; другие providers не подтверждают произвольную взаимозаменяемость миров. |
| `render.software3d`, `render.rasterize`, `viewport.output` | Существующие контракты software/viewport; корневой/вложенный граф предпросмотра. |
| `scalar.value`, `clock.time`, `interface.input`, `interface.output` | Существующие scalar/interface-контракты с применимыми подсказками корневого/рендерного графа. |
| `custom.rust`, `custom.rust.update` | Общие hosts скомпилированного Custom; исходник Rust и соответствующий корневой/исполняемый граф. Пользовательский код сохраняет собственную принадлежность. |
| `game.motion` | Прежние данные компонента примера; поля компонента. |
| `render.vulkan`, `gpu.forward`, `gpu.gbuffer`, `gpu.deferred`, `gpu.depth_normal`, `gpu.ssao`, `gpu.tonemap`, `gpu.fxaa`, `gpu.color_encode`, `gpu.custom` | Установщик Vulkan; подсказки корневого/рендерного графа и HLSL. Описания объясняют каждый настоящий проход, включая AO и AA текущего кадра. Регистрация не открывает устройство. |
| `game.input`, `game.ai`, `game.movement`, `game.collision`, `game.combat`, `game.health`, `game.portals`, `game.audio` | Установщик ARPG; исполняемый граф, компоненты и нативные исходники. Последняя запись адаптирует игровые события; нативное воспроизведение звука отдельно. |
| `puzzle.turn`, `puzzle.result` | Установщик исходной Puzzle; исполняемый граф и компоненты. Её лимит ходов не меняется из-за неограниченных ходов G1. |
| `g1.rules` | Установщик Crate Garden; исполняемый граф, зарегистрированный инструмент уровня и нативные исходники. |
| `example.spin` | Установщик исходного расширения приложения; исполняемый граф и поля компонента Rotation. |
| `arpg.presentation`, `puzzle.presentation`, `g1.presentation` | Настоящие игровые вклады `SystemRegistry` и отдельно предоставленные описания. Активация следует объявленным модулям расписания. |
| `audio.wav`, `persistence.json` | Настоящие фабрики `HostServiceRegistry` при установке соответствующих features. Точкой настройки остаётся исходный код запросов/конфигурации; общее окно настроек звука не подразумевается. |
| `game-kit.actions`, `game-kit.grid`, `game-kit.history`, `game-kit.campaign` | Выбранные компиляцией чистые API game-kit, показанные через объявленные зависимости установленных исходных потребителей. В нынешнем составе G1 объявляет эти четыре зависимости. Нативные исходники/сборка, а не переключатель runtime. |
| `editor.panel.100`, `editor.panel.110` | Настоящие регистрации Editor: Participating Modules и Crate Garden Level Palette. Метаданные объявляют назначение/владельца; доступность сохраняет проверки активности владельца и прав Engine. |

Это семейства установки, а не обещание наличия каждой строки в любом бинарном
файле. Меньшие составы features не включают соответствующие пакеты, сервисы и
библиотеки потребителей. Код каркаса — импорт контента, история, компиляция
workers, проверка проектов и встроенные окна — по-прежнему описывается
существующими пакетами/контрактами; список не создаёт опциональные runtime-узлы
для каждой функции каркаса. Он не объявляет полный список всего связанного
линкером библиотечного кода.

## Доказательства состояний

`CapabilityRecord` отдельно хранит `installed`, необязательную объявленную
`version`, `available` и `participation`. `CapabilityFact` — необязательный Boolean
и его `evidence`: `null` означает неизвестность, а не выключение. Заявлений
`running`, `compiled` или `ready` нет. Версия отсутствует там, где реестр не
предоставляет отдельно версионируемый контракт, в том числе у сервисов,
инструментов и host hooks.

| Вид | Доказательства доступности и участия |
| --- | --- |
| Модуль/система | Установленные контракты `CompositionContext`; предоставленные ID профиля Engine. Участие берётся из `CompositionContext::activity`, включая связанные модули графа, включённые features схем, системы расписания и активных владельцев схем. |
| Вклад в host | Профилем предоставлен хотя бы один модуль активации; участие следует существующему правилу авторского расписания. Связи `activated_by_any` — альтернативы, а не обязательное наличие всех зависимостей. |
| Сервис | Установленная фабрика и объявленная исходниками поддержка платформы/реализации без проверки устройств/файлов. Участие означает явный запрос от существующих чистых `service_requests` активных вкладов. |
| Библиотека | Выбранная компиляцией библиотека, объявленная установленным потребителем; участие означает объявленную зависимость участвующего модуля, а не наблюдаемое выполнение функций. |
| Панель/инструмент редактора | Настоящая регистрация; доступность определяют участие владельца и существующие проверки `engine_only`. Активный владелец не означает открытое окно или выполненный callback. |

Представление Core принимает необязательный набор предоставленных ID от
вызывающей стороны. Объединение Player читает `EngineProfile::from_document` и
применяет существующие переносимые проверки `validate_document` перед передачей
набора. Отсутствующий/ошибочный профиль оставляет доступность модулей неизвестной.
Это не подтверждение нативного пакета/SDK, не предоставление прав редактирования
и не результат полной проверки проекта.

Ошибка определения активности оставляет участие неизвестным, в том числе для
сервисов и библиотек; она не превращается в пустое активное множество. Известный
пустой набор предоставленных ID отличается от отсутствующего доказательства.
Неизвестные модули и отсутствующие фабрики сервисов остаются видимыми с
диагностикой; неописанные метаданные сохраняют неизвестного владельца/пакет
вместо догадок. Поэтому запрошенный недоступный звук может иметь
`participation=true` и `available=false`. На Windows и Linux доступность звука
обозначает скомпилированный backend. Устройство выбирается при первом
включённом сигнале, и тогда становятся видны ошибки вывода.

Авторское участие не означает включённость прохода, полную корректность графа,
скомпилированный shader или работающий Play. Включение проходов, прогресс workers,
готовность устройства и права авторства остаются отдельными контрактами.

## API, зависимости и сохранность

- `ModuleRegistry::describe_module` и `SystemRegistry::describe_module`
  прикрепляют исходные метаданные к установленным ID. Отсутствующие владельцы и
  конфликтующие описания отклоняются. Композиция переносит название/назначение
  описанной системы, не меняя её исполняемый дескриптор, фабрику или версию.
- `SystemRegistry::describe_contribution` описывает настоящие зарегистрированные hooks.
- `CompositionContext::capability_inventory` строит представление модулей.
  `capabilities::capability_inventory` Player объединяет сведения профиля,
  вкладов, сервисов и объявленных библиотек. Фабрики рендера/систем/сервисов,
  такты и UI callbacks не вызываются; существующий чистый поиск запросов сервисов
  — отдельное разрешённое действие.
- `HostServiceRegistry::capability_inventory` читает фабрики и запросы без
  разрешения ресурсов, чтения сохранений, создания папок или открытия аудио.
- `module_panel_capabilities` Editor описывает настоящие регистрации панелей
  без вызова инструментов и создания их нового состояния. Это доступ только
  для чтения для обзора; callback панелей при этом не выполняются.

Виды зависимостей сохраняют смысл: `active_module` — существующие зависимости
модулей, `preceding_system` — исполняемый дескриптор, `library` — объявленное
использование библиотек, `activated_by_any` — активация вкладов host. Также
перечислены ID предоставляемых схем и статически объявленных потребляемых
компонентов. `params.components` экземпляров Custom влияет на каноническую
активность, а не на этот статический список дескриптора. Условные требования
полей и схем остаются в нынешних контрактах; отчёт не заменяет все валидаторы
плоским списком.

Подсказки настройки определяют категории инструментов, а не гарантированные
доступные кнопки. Engine Overview определяет цели перехода и права через
существующие операции. Обычные изменения нативного кода требуют сборки.
Неизвестные сторонние метаданные сохраняют неизвестность без классификации
по префиксу ID. Просмотр не сохраняет, не обновляет pins, не мигрирует и не
меняет документ. Новые зависимости, динамический бинарный ABI и авторский
формат не вводятся.

## Диагностический пример только для чтения

С существующими настроенными нативными инструментами/кешем:

```text
cargo run --offline --locked --target x86_64-pc-windows-msvc -p module-engine-player --all-features --example capability_inventory -- <fixture.json> <source-root>
```

Пример печатает список JSON; он не записывает проект и не создаёт неиспользуемую
диагностическую папку состояния. Features выбираются для настоящего изучаемого
бинарного файла. Без `--all-features` отсутствующие пакеты не придумываются.
Эта диагностика исходников не разрешает привязку пакета проекта Editor и не
заменяет проверки Full/Team/экспорта, осмотр UI или приёмку runtime.
