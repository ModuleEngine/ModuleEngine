# 0.4.2 — заголовки отдельных панелей и закрытие экземпляра

[English](../release-042-native-panes-verification.md) | [Русский](release-042-native-panes-verification.md) | [Документация](README.md)

Дополнение сохраняет общий документ, историю и Play-сессию и объединяет заголовки
основных и отделённых областей. Рендеринг, FXAA, SSAO, форматы проекта и права
Full/Team не меняются. Существующий шейдер SSAO сохранён с SHA-256
`65c9b086813cd25da93ae36408f23d3e0e084867665aa17b468e7773a1395a92`.

## Поведение

Клиентский заголовок использует общие с основной областью выбор редактора,
**Area** и свободное место переноса. Меню **Area** — векторное вертикальное
троеточие справа с подсказкой/именем доступности Area. По окончательному предпочтению владельца
отделённые окна сохраняют заголовок/название ОС, системный **×** и нативную рамку
изменения размера краями/углами. Внутри нет второго **×** и строки File/Edit.
Оформление ОС не переключается во время переноса, сохраняя нативный capture;
перенос за клиентский заголовок учитывает внешнее начало и сохраняет полный
размер клиентской части. Закрытие доступно в меню области; отдельной кнопки закрытия внутри заголовка нет.

**×**, **Area → Close area** и системное закрытие убирают только этот экземпляр
со стабильным ID. Соседние области того же типа сохраняют состояние; проект
не закрывается. В сохранённой раскладке отсутствуют закрытый экземпляр и его
память панели. Повторное открытие через Windows использует обычное существующее
поведение поиска/открытия. Закрытие во время переноса завершает его без отката,
который мог бы восстановить закрытый экземпляр в раскладке.

**Area → Return to main window** и docking перетаскиванием остаются явными
действиями. Они сохраняют ID/состояние вида; Return использует безопасное доступное
место, если прежний сосед изменился. Защита последней основной области сохранена.

## Исследование resize

Исходное нативное окно с системным заголовком проверено в изолированной Full-копии
с готовой Scene размером 760×510 логических точек. System Size изменил ширину
760 → 749 → 738; образцы изменившейся геометрии не показали возвратов и колебаний.
Первый запуск fixture не получил настроенный offline-кеш Cargo и не смог собрать
Custom; ошибка окружения устранена до наблюдения готовой Scene.

Это **не** воспроизводит и не доказывает исправление сообщённого дрожания при
медленном resize с удержанием. Computer Use не умеет вводить медленную траекторию,
держать кнопку на границе и затем отпускать; снимки также не содержат внешнюю
рамку изменения размера окна с системным заголовком. Быстрые автоматические
перетаскивания краёв этот жест не подтвердили. Спекулятивная правка обратной связи
геометрии не засчитывается как исправление дрожания. Необязательный
`MODULE_ENGINE_AREA_GEOMETRY_TRACE` выводит до 2048 изменившихся образцов на
нативную область: время, фактическую сохраняемую геометрию, запрошенные
координаты/размер и масштаб — для следующего различающего измерения.

## Свидетельства и оставшиеся проверки

Свидетельства находятся в `outputs/native-panes-042` и `work/native-panes-042`.
Исходные/кандидатные копии и изолированные личные каталоги не заменяют опубликованную
SSAO-поставку и личные раскладки пользователя. Пакет ревью с привязкой к исходникам
находится в `outputs/reviews/native-panes-042`.

Предыдущий кандидат без рамки (сохранён как промежуточное свидетельство) подтвердил
общий клиентский заголовок, явный Return к двум
основным Scene того же типа, повторное отделение и удаление только отделённого
экземпляра по ×. Сохранённый JSON содержит Scene ID 2 с её памятью и не содержит
отделённой области. Финальные проверки, артефакты и независимое заключение записаны
в пакете ревью; промежуточные нативные наблюдения не являются полной приёмкой релиза.

Физические медленные движения края/угла с удержанием на границе и отпусканием,
перенос между мониторами с разным DPI, аппаратный Linux и приёмка картинки владельцем
остаются отдельными проверками. Для ручной проверки откройте Scene в отдельном
окне, медленно меняйте размер каждым краем и углом, удерживайте и отпускайте;
наблюдайте отдельно геометрию ОС, раскладку заголовка/содержимого и изображение Scene.
После изменений повторяйте те же размеры. Дважды перенесите плавающий заголовок,
выполните docking или явный Return, создайте два экземпляра Scene, закройте один
по × и один системной командой, перезапустите и снова откройте через Windows.
Соседи того же типа должны сохранить состояние; закрытый экземпляр не появляется.
