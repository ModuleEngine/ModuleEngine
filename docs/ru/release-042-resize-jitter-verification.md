# Проверка обратной связи размеров нативных окон

[English](../release-042-resize-jitter-verification.md) | [Русский](release-042-resize-jitter-verification.md) | [Документация](README.md)

Владелец записал чередование ширины803/805 физических пикселей в текущем Full
с исходным значком: неизменные начало(797,156) и высота803px. Двенадцать
последовательных кадров за2,59сек показывают восемь изменений ширины. Это заменяет
прежнее «не воспроизведено»; старые отчёты сохраняют исторический смысл.

Причина — задержанная обратная связь геометрии. Раньше каждый immediate viewport
builder получал последний сохранённый нативный размер/положение. Callback читает
геометрию до применения egui-winit изменённого запроса builder; замер затем
сохраняется и отправляется обратно на следующем кадре. Закреплённый egui0.36.2
сравнивает запросы builder, а не текущий прямоугольник ОС. Поэтому одна пара
рассинхронизированных размеров может поддерживать чередование без внешнего ввода.

Отдельная скрытая проба настоящего Editor/Scene в своём процессе использует
production Editor.ui/draw_detached_areas и точный привязанный HWND. При803/805
движение с шагом100мс сходилось после остановки; асинхронное движение6мс дало
восемь изменённых устаревших запросов, но также сходилось. Это контроли, а не
самопроизвольное воспроизведение остановки владельцем. Один управляемый устаревший
сохранённый замер после остановки затем воспроизвёл продолжающееся чередование
803/805. Итоговая парная проба имеет явные последние команды803/805, интервалы
без ввода при обеих ширинах и одну фазовую инъекцию из client789 в stored787
около9,2сек. Baseline сохранял обе внешние ширины в последнем интервале без ввода;
исправление однократно выполняет явную цель и стабилизируется. Фактически выданные
команды — в external-commands.json. Ранние подсказки root-замеров не служат
источником истины и удалены из итогового парного harness. Управляемая инъекция
показывает причинную границу, но не заявляет самопроизвольного физического
воспроизведения остановки владельцем.

Исправление сохраняет наблюдения ОС без создания обратных команд. Временный
tracker по полному workspace key и стабильному host ID сравнивает только
геометрию/масштаб/рабочие области и учитывает разрешённый readback после его
сохранения. Создание/пересоздание получает геометрию builder; явное намерение для
существующего хоста однократно отправляет InnerSize/OuterPosition в уже созданном
дочернем контексте. Команды изымаются из очереди, поэтому повтор callback
после request_discard не добавляет их второй раз. Это также восстанавливает цель, равную старому запросу builder,
после пользовательского изменения размера. Кадры наблюдения не задают геометрию
ни builder, ни командами. Защита drag/pending-readback, размещение при смене
мониторов/масштаба и отсутствие явного положения на Wayland сохраняются. Debounce,
мёртвая зона resize, правила округления и принудительное разрешение рендера не добавляются.

Целевые регрессии проверяют наблюдения без команд, точную отправку исходных760×510
и(64,64) после800×600/(797,156), отсутствие эха старого замера, явные перемещения,
пересоздание/мониторы/масштаб и прежнюю геометрию drag с OS-рамкой. Парная проба
настоящего Editor проверяет интервалы без ввода и записывает наличие запросов.
Исходники, полные логи, хеши fixture/проекта и итоговые артефакты находятся в
work/resize-jitter-042 и outputs/resize-jitter-042. Временные диагностические точки
входа, скрытие окон и include work-модуля удалены до поставки; остаётся только
ограниченный opt-in trace геометрии. Full обычно запечатан, Team обычно
экспортирован; обхода package pin нет.

Прежние поставки и активное окно владельца не тронуты. Исходный ICO, Area parity,
SSAO и100% Scene сохранены. Computer Use не возобновляется после прежнего
конфликта ввода владельца. Физические визуальная проверка/удерживаемый указатель и
mixed-DPI остаются открытыми; целевая нативная регрессия не является утверждением
о любом resize, аппаратных платформах или производительности.
