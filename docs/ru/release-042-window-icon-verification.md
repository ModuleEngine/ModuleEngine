# Проверка значка окон Editor

[English](../release-042-window-icon-verification.md) | [Русский](release-042-window-icon-verification.md) | [Документация](README.md)

После [поставки хостов областей](release-042-area-hosts-verification.md) владелец
сообщил об отсутствии значка работающего Editor в окне/панели задач и указал
существующий оригинальный значок. Первоначальный придуманный куб был ошибкой и
удалён. Исходный установленный ICO побайтно скопирован в
`crates/editor/assets/editor.ico`; SHA-256
`774d701d80d2f7ede634a228075d58627e2887d3776a08ed07136a3223200e9a`.
Источник — IconLocation ярлыка Module Engine на рабочем столе:
`C:\Users\MyJname\AppData\Local\ModuleEngine\Icons\editor-774d701d80d2f7ed.ico,0`.
Чёрный скруглённый квадрат и белый модульный шестиугольник используются без
перерисовки. В ICO сохранены все семь исходных PNG-кадров
(16/24/32/48/64/128/256).

Главный и плавающие builders используют общий кешированный `IconData`,
декодированный из точного кадра 64px существующим механизмом eframe. Размеры
малого/большого значка Windows берутся из системных метрик: при наличии выбирается
точный исходный кадр, иначе наименьший больший (либо наибольший доступный), который
декодирует/масштабирует Windows. Предпросмотр 256px — точно извлечённый исходный
PNG, без перерисовки. Новых зависимостей, сгенерированной замены и смены оформления нет.

В закреплённом eframe 0.36.2 указано, что winit задаёт только `ICON_SMALL`;
резервный механизм один раз задаёт оба слота через `GetActiveWindow`, что не
привязывает все плавающие хосты. Поэтому существующая точная привязка HWND своего
процесса назначает `ICON_BIG` и `ICON_SMALL` при первом получении/пересоздании.
Кешируются два handle на время процесса. Исходные PNG-кадры передаются в
`CreateIconFromResourceEx`; заимствованные прежние handle не уничтожаются. При
частичном сбое новой пары освобождается только её новый handle. Неверный/чужой
HWND отклоняется; `WM_GETICON` проверяет оба назначения.

Точный путь ICO обязателен для native source, входит в обычную опись исходников
Full и экспорт. Существующий тест полноты проверяет сохранение при запечатывании,
отклонение отсутствующего файла или пропущенного pin и отсутствие неявного
разрешения посторонних ICO. Широкого правила ресурсов и ручного обхода
манифестов/pin нет.

Release-проверка `app_icon::tests --include-ignored --test-threads=1` проверяет все
семь исходных кадров и размеров, точные декодированные пиксели 64px, выбор
резервного размера, общий кеш и два настоящих скрытых окна Win32 вне экрана.
Назначение главному окну не меняет другое; после назначения обоим малый/большой
слоты ненулевые и равны. Неверный HWND отклоняется. Это проверка native-слотов,
а не наблюдение фактической панели задач. Функции областей сохраняют прежние
границы независимых доказательств; нативный набор для этой коррекции не повторяется.

Исходники, команды, предпросмотр и хеши находятся в `work/window-icon-original-042/`
и `outputs/reviews/window-icon-original-042/`. Исправленный отдельный кандидат —
`outputs/area-host-parity-042/original-icon/`: Full обычно запечатан, Team обычно
экспортирован. Прежние поставки не меняются.

Computer Use ранее остановлен при явном вводе владельца в старом окне Full.
Его дальнейшая активация, перезапись или закрытие не выполняются. Фактический вид
значка работающего Editor в заголовке/панели задач, физический DPI и визуальная
приёмка владельцем остаются открытыми. Ресурсы самого EXE и оформление Player
не меняются.
