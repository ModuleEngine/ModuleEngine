# Модели, анимация, текстуры и материалы

[English](../content.md) | [Русский](content.md) | [Документация](README.md)

Контент загружается отдельной библиотекой `module-engine-content`. Мир хранит объекты и их устойчивые ID; библиотека присоединяет геометрию и материалы к извлечённому `SceneSnapshot`. Поэтому Object и ECS используют одинаковые файлы, а renderer получает одну нейтральную структуру.

## Что загружается

Поддерживаются glTF 2.0 `.gltf` и `.glb` с индексированными и неиндексированными треугольными примитивами, иерархией узлов, трансформациями translation/rotation/scale или matrix и UV-набором 0. Импортёр читает внешние `.bin`, PNG/JPEG, встроенные изображения в bufferView и base64 data URI. Составной меш сохраняет отдельные примитивы и материалы. Импортёр переводит матрицы glTF в построчное хранение и компонует их с трансформацией игрового объекта.

Импортёр читает основные metallic/roughness-материалы, в том числе нормали, тангенсы, все пять карт и их коэффициенты. RGB базового цвета и свечения использует sRGB. Карта metallic/roughness хранит металлическость в B, а шероховатость в G. Затенение берётся из R и влияет на фоновое освещение. Карта нормалей задаёт XY в касательном пространстве, Z восстанавливается. Если меш не содержит тангенсов, рендерер вычисляет касательный базис по градиентам позиции и UV. Импортёр отклоняет morph targets, sparse accessors, нетреугольные примитивы, обязательные расширения и карты с другим UV-набором. Для линз FlightHelmet используется основной материал glTF при наличии необязательного расширения transmission.

Штатные пути Forward и Deferred используют GGX BRDF, фиксированный направленный источник и фоновое освещение. Непрозрачный материал игнорирует alpha текстуры. Mask записывает цвет и глубину только для фрагментов, у которых alpha достигает порога. Blend рисует примитивы от дальних к ближним в линейном HDR до тональной компрессии. Он учитывает глубину непрозрачной геометрии и оставляет её без изменений. Ключ сортировки вычисляется на примитив. На пересечениях прозрачной геометрии возможны артефакты порядка. Односторонний материал отсекает обратные стороны, двусторонний переворачивает нормаль обратной стороны для освещения. Custom scene raster сохраняет собственный интерфейс базового цвета.

PNG/JPEG также можно назначить существующей геометрии. Коэффициент материала и цвет объекта умножаются на линейный RGB. Индексируемый путь Vulkan использует повторение UV, mip-фильтрацию и анизотропию. Атлас совместимости берёт ближайший тексель и декодирует цветовые слоты из sRGB в HLSL. Параметры семплера задаёт движок. [Пути материалов Vulkan](hardware-tiers.md#r22-materials).

## Анимация glTF

Импортёр загружает скины, используемые сценой по умолчанию. Если она не задана, он берёт первую сцену файла. При импорте сохраняются порядок и иерархия суставов, обратные матрицы привязки и парные атрибуты `JOINTS_n`/`WEIGHTS_n`. Если обратные матрицы не заданы, используются единичные. Целочисленные веса читаются из нормализованных accessors. Неотрицательные веса вершины нормализуются совместно по всем наборам её влияний. Суставные матрицы деформируют вершины в пространстве сцены glTF, затем движок применяет трансформацию авторского объекта.

Клипы сохраняют порядок в файле, имена при наличии и длительность. Дорожки переноса, вращения и масштаба поддерживают `STEP`, `LINEAR` и `CUBICSPLINE`. Линейное вращение использует интерполяцию кватернионов по кратчайшей дуге. За пределами своей временной шкалы дорожка удерживает первый или последний ключ. Время зацикливается по длительности клипа. `LoadedModel::animation_clips()` возвращает список клипов, а `LoadedModel::sample_clip(index, seconds)` вычисляет нейтральную геометрию для одного клипа по индексу с нуля. В `LoadedModel::primitives` хранится исходная поза модели для предпросмотра ресурсов.

Модель назначается обычной ссылкой `mesh.path`. GameHost автоматически проигрывает первый клип с дорожками в выбранной сцене по времени кадра, вычисленному из принятого игрового времени. Предпросмотр Scene в нулевой момент показывает первый сэмпл. Pause удерживает текущее время, Restart возвращает его к нулю. CPU вычисляет деформированные вершины, а Vulkan рисует их через поток вершин кадра. GPU skinning, смешивание клипов и граф анимации относятся к следующим этапам.

## Ссылка из сцены

В компонентах авторского объекта или экземпляра шаблона:

~~~json
{
  "mesh": {"path": "assets/models/demo_crystal.glb"},
  "material": {
    "base_color": [1.0, 1.0, 1.0, 1.0],
    "base_color_texture": "assets/textures/stone.png"
  }
}
~~~

Компонент `material` необязателен: без него используются материалы glTF. Поля override также необязательны. Неизменённые встроенные объекты используют кубы; импортированный объект рисует свои вершины и треугольники. `demo_crystal.glb` — собственный маленький тестовый кристалл с встроенной PNG-текстурой.

## Ресурсы Surface Material

В Assets выберите **New material…**, затем выделите файл и откройте **Edit material…**. В Inspector добавьте объекту **Surface Material** и назначьте файл. Примените правку Inspector и редактируйте файл при остановленном Play. Правка файла действует на все объекты, которые ссылаются на его стабильный ID. Сохраните проект и экспортируйте его, чтобы использовать эти значения в Player. В Full-проекте со старым профилем Vulkan используйте **Publish Engine profile / update contracts**. В Team действуют установленный профиль и его точные pins.

```json
{
  "schema_version": 1,
  "roughness": 0.35,
  "normal_texture": "assets/textures/helmet-normal.png"
}
```

ID компонента — `surface_material`, поле ссылки — `asset`. Файл `.material` хранит JSON-объект размером до 64 КиБ. Отсутствующее поле или null наследует значение материала. Сначала применяются старые overrides компонента `material`, затем правки из файла. Одна привязка объекта действует на каждый его примитив и сохраняет значения glTF в наследуемых полях. Файл поддерживает `base_color`, `metallic`, `roughness`, `normal_scale`, `occlusion_strength`, `emissive`, `alpha_mode`, `alpha_cutoff`, `double_sided` и пять слотов текстур. Текстуры задаются путями PNG/JPEG относительно корня проекта. Assets отслеживает зависимости, обновляет их пути при перемещении и записывает правки и изменения зависимостей в файловые Undo/Redo. [API Assets](asset-workspace-api.md).

## API и жизненный цикл

`ContentLibrary::new(package_root)` фиксирует корень конкретного проекта/пакета. `load_model(path)` возвращает кешированный `Arc<LoadedModel>`. `enrich_snapshot(snapshot, bindings)` заменяет кубы объектов с указанными ID на примитивы модели, сохраняя трансформацию и цвет объекта. Несколько примитивов имеют исходный ID объекта. `load_texture(path)` возвращает кешированный `Arc<TextureImage>` для material override. Текстуры разделяются между снимками через Arc; они не декодируются заново каждый кадр.

`invalidate()` очищает декодированный кеш после изменений ресурсов. При открытии другой игры создаётся другая библиотека с её корнем. Смена модели мира не меняет правила чтения файлов или material ABI.

`import_model(source, destination_directory)` проверяет модель и все относительные зависимости, затем копирует их с сохранением структуры. Корень исходного импорта — каталог выбранной модели; зависимости вне этого каталога при импорте отклоняются. Если исходник использует соседний каталог через `../`, сначала поместите комплект ресурсов в проект и загружайте его от корня проекта. `import_texture(source, destination_filename)` сначала декодирует PNG/JPEG и только затем записывает файл в проект.

Импорт модели в Editor и Apply файла материала готовят цепочки mip-уровней в `.work/texture-bc`. Ключ кеша учитывает декодированные пиксели, размеры, назначение карты и версию кодирования. BC7 хранит карты базового цвета и свечения в sRGB, metallic/roughness и затенение в линейном пространстве. BC5 хранит XY карты нормалей. Mip-уровни базового цвета фильтруются в линейном пространстве с учётом alpha в режимах Mask и Blend. Для базового цвета в режиме Opaque и для свечения усредняется линейный RGB независимо от alpha. Нормали усредняются как направления и нормализуются. Индексируемый рендерер загружает BC-уровни при поддержке устройства. Другие устройства используют декодированные пиксели. При повреждённом или отсутствующем кеше загружается исходное изображение.

## Владение файлами и экспорт

Пути игровых ресурсов относятся к выбранному пакету. Абсолютные пути и URL не используются. Внешние URI glTF разрешаются относительно каталога glTF; percent-encoding декодируется до проверки. Canonical path обязан остаться внутри пакета, включая цели символических ссылок. При загрузке относительный `../` разрешён только если результат остаётся внутри корня проекта. При копировании проверяется также существующая цель файла.

`dependencies(model_paths)` возвращает полное множество файлов моделей, буферов и изображений для экспорта. Встроенный `.glb` даёт один файл. Для внешнего `.gltf` учитываются документ и файлы, на которые он ссылается. Экспортёр также собирает активные файлы материалов и отдельные текстуры из overrides. Vulkan Player включает производные mip-цепочки в `.textures` с хешами в `player.json`. При экспорте блоки из кеша переиспользуются только при совпадении пикселей и назначения карты. Player читает файлы из своего пакета и использует сохранённые исходные изображения для совместимости.

Ограничения загрузки: 128 MiB на файл модели, буфера или кодированной текстуры, текстура до 4096×4096, лимит декодирования 128 MiB, до миллиона вершин в примитиве и трёх миллионов элементов accessor, до 4096 узлов и 128 уровней иерархии. Диапазоны в бинарных данных проверяются до создания итератора. Индексируемый рендерер использует отдельные GPU-изображения в пределах лимитов устройства. Атлас совместимости допускает до 8192 пикселей по каждой оси. Потоковая загрузка текстур для больших игр остаётся отдельной задачей.

На одну анимированную модель допускаются до 32 768 привязок суставов в используемых скинах, восьми миллионов записей о влиянии на вершины и восьми миллионов скалярных компонентов выборок анимации.

## Проверка

~~~powershell
cargo test --locked -p module-engine-content --features texture-bake -p module-engine-vulkan
~~~

Тесты импортируют bundled GLB, внешний glTF с `.bin` и PNG, копируют весь комплект и загружают самостоятельный JPEG. Проверяются матрицы узлов и отказы для внешних/закодированных обходов путей. Vulkan-тест отдельно подтверждает, что UV и текстура импортированного mesh меняют реальные пиксели Forward и Deferred; повторный кадр после использования кеша совпадает.

<a id="r51-material-check"></a>

Для проверки R5.1 сохраните исходную структуру каталогов Khronos и возьмите ревизию `e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea`. Список входов и хеши приведены в [material_khronos_sha256.txt](../../crates/editor/src/material_khronos_sha256.txt). Проверке нужны Full с доступом к исходникам, Vulkan с индексируемыми BC-текстурами, DXC и нативные инструменты сборки Player. На общем стенде подавайте `r5-materials` через [локальную очередь](local-queue.md). Она импортирует встроенный DamagedHelmet и внешний FlightHelmet, проверяет атрибуты и назначение карт и сохраняет фактические кадры Forward и Deferred. Два значения шероховатости применяются через транзакцию Editor. Проверка экспортирует оба пакета и сверяет отдельный кадр каждого Player с авторским предпросмотром. Синтетические Vulkan-тесты проверяют Mask, сортировку Blend и глубину непрозрачной геометрии. [Khronos DamagedHelmet](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea/Models/DamagedHelmet), [Khronos FlightHelmet](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea/Models/FlightHelmet).

~~~powershell
$id = & "$queue/submit.ps1" -Worktree (Get-Location).Path -Commit (git rev-parse HEAD) -Check r5-materials -Author R5.1
& "$queue/result.ps1" -Id $id -FullLog
~~~

Тест скина проверяет иерархию суставов, обратные матрицы привязки, нормализованные целочисленные веса и отказ до копирования при неверной размерности accessor весов. Для нативной проверки нужны оригинальные GLB Khronos из ревизии `e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea`, Vulkan и DXC. Поместите оба файла в каталог `MODULE_ENGINE_R71_SAMPLES` и укажите в `MODULE_ENGINE_R71_OUTPUT` новый каталог свидетельств с существующим родителем. Тест сверяет хеши файлов, вычисляет позы всех клипов и сохраняет PNG от GameHost на тиках 0, 27 и 54 для клипов по умолчанию и статического кристалла. Проверяются деформация, различие пикселей, удержание позы, перезапуск и совпадение пикселей статического образца. [CesiumMan GLB](https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Assets/e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea/Models/CesiumMan/glTF-Binary/CesiumMan.glb), [Fox GLB](https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Assets/e124e8d8d7330a5372bc2b4d00d39a4a9d7997ea/Models/Fox/glTF-Binary/Fox.glb).

~~~powershell
cargo test --offline --locked -p module-engine-host --test gltf_playback -- khronos_glb_import_and_play --ignored --exact --nocapture --test-threads=1
~~~

Формат реализован по [спецификации Khronos glTF 2.0](https://github.com/KhronosGroup/glTF/tree/main/specification/2.0); список поддержанных возможностей выше задаёт фактическую границу этой версии.
