# R8.1. Эксперимент с mesh shaders на S5

[English](../r81-s5-meshlets.md) | [Русский](r81-s5-meshlets.md) | [Документация](../README.md)

R8.1 сравнивает две явные команды бенчмарка в сборке Editor из исходников.
Обе используют исходную сцену S5 из 40 участков с 20 000 000 индексированных
треугольников и 10 040 040 вершинами, камеру фикстуры и штатный граф Forward
при 1920×1080. В рабочем рендерере сохраняются действующие правила выбора
устройства, ABI шейдеров и отправки сцены.

- `S5-r24` строит существующую retained-сцену и использует R2.4 Hi-Z
  вместе с indexed indirect count. Команда требует активного пути R2.4 и
  записывает число команд после отбраковки. В её логическом устройстве Vulkan
  mesh shaders выключены.
- `S5-r81` строит meshlets в памяти через `meshopt` 0.6.2 с ограничением
  64 вершины и 124 треугольника на meshlet. Одна группа task запускает до
  32 групп mesh. Каждая группа mesh преобразует индексированные вершины,
  вычисляет плоские нормали и записывает исходные идентификаторы треугольников
  и объектов. В статическом прототипе task-шейдер запускает все meshlets.
  Счётчики отражают отправленную работу. Команда требует возможностей task
  и mesh из `VK_EXT_mesh_shader` и индексированных материалов Forward.

Стоимость построения включает кластеризацию, восстановление исходного
порядка вершин в пределах треугольника и упаковку для загрузки. Оба пути
загружают сцену один раз и рисуют из буферов в памяти устройства. В область
эксперимента входят измерения статического пути. Хранение meshlets в ассетах,
проверка видимости отдельных meshlets, кэширование импорта, LOD и порог
60 FPS этапа R8.3 относятся к следующим этапам.

## Воспроизведение

Используй эталонный Windows GPU без конкурирующей нагрузки и закреплённую
в проекте версию DXC. Возьми исполняемый файл из результата bench-сборки
и сохрани путь к этому артефакту в отчёте.

```powershell
cargo build --locked --release -p module-engine-editor --features bench
python -B scripts/bench_r81.py --exe <bench-exe> --output outputs/r81/series
```

Сравнение сначала считывает оба изображения 1080p. Оно проверяет устройство,
размер, совпадение всех счётчиков RenderStats, наличие пикселей с геометрией
и абсолютное отклонение до 2 на каждом канале RGBA8. Обе PNG и отчёт по
изображению сохраняются. Замер затем запускает пять пар нативных процессов,
меняя порядок путей в соседних парах. Каждый процесс прогревается пять
кадров и записывает 30 нативных кадров с GPU timestamps, без переноса
пикселей на CPU, с выключенным vsync и режимом представления Immediate.
Оба пути должны сообщить одинаковые параметры представления, сцены и
устройства и подтвердить ожидаемый способ отправки геометрии в каждом
кадре. Отчёт содержит медианы средних и p95 по прогонам, допуск по разбросу
R2.4, пиковый рабочий набор процесса, счётчики аллокатора рендерера,
разовую подготовку и загрузку геометрии и число команд рисования. Счётчики
аллокатора объединяют учитываемые им пулы. Пик общего расхода VRAM отдельно
не измеряется.

Отдельно запусти проверку изображений в debug-сборке с активными Khronos
validation layer и проверкой синхронизации через
`--bench-scene R81-visibility <new-output>`. Сохрани журналы компилятора и
процессов и хеши исходников и сборок. См. [проверки R2.4](bench.md#r24-culling-checks),
[возможности и ограничения mesh shaders](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_mesh_shader.html)
и [атрибуты SPIR-V в DXC](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/SPIR-V.rst).
