# R1.10 — типизированный тик ARPG

[English](../../../evidence/r110-arpg/README.md) | [Русский](README.md) | [Документация](../../README.md)

Нативное расписание ARPG сохраняет типизированный `ArpgFrame` в ресурсе Bevy
на время одного тика. Его восемь узлов используют одно декодирование и одно
итоговое кодирование. Переносимые узлы между ними получают актуальный JSON,
вызывая публикацию и последующую повторную загрузку. Границы определены в
[контракте расписания](../../module-execution.md).

## Парное измерение Windows

База — `a38f6426480c97f20c9d9fab1e62b7800841d427` с добавленным
[примером измерения](../../../../crates/game-host/examples/r110_arpg.rs).
Обе версии используют Rust 1.99.0, `x86_64-pc-windows-msvc`, Release с
`opt-level=2`, стандартные флаги, Windows 10.0.26300 и AMD64 Family 23 Model
113 Stepping 0. Фикстура повторяет [бой RV-C](../../../evidence/rv-c-arpg/README.md),
120 тиков прогрева и 600 измеряемых тиков, 20 живых врагов, неизменное
нативное расписание из восьми узлов и детерминированный ввод перемещения
и ближнего боя. Каждый процесс создаёт новый headless `GameHost`. Рендер,
скомпилированный Custom и нативные сервисы находятся за пределами фикстуры.

Семь пар запускались последовательно с чередованием порядка версий и без
конкурирующей сборки. В таблице приведены медианы семи средних по прогонам
и семи p95 по ближайшему рангу, в микросекундах. Среднее время фиксированного
тика улучшилось в каждой паре, от −34,74% до −48,89%.

| Область | База, среднее / p95 | Типизированная версия, среднее / p95 |
| --- | ---: | ---: |
| Фиксированный тик | 980,00 / 1 285,90 | 559,55 / 716,30 |
| Среднее `GameHost::step` | 982,55 | 562,33 |

Медиана среднего времени фиксированного тика уменьшилась на 42,90%. Обе
версии создали ровно 159 событий `Attack`, 391 `Hit` и 550 `Sound`. Во всех
14 прогонах совпали хеши фикстуры, полной последовательности событий и
принятого состояния. Хеш принятого состояния включает мир, ID воплощений
во время исполнения, переносимые данные модулей, control и JSON-состояние
каждого экземпляра. [Исходные отсчёты, хеши и окружение](../../../evidence/r110-arpg/measurements.json)

## Отклонение и повтор

Пример добавляет узел после ARPG audio, который записывает ресурс,
состояние экземпляра, `module_data`, событие и control, затем отклоняет
публикацию в `commit_tick`. Принятое состояние и ID воплощений полностью
совпадают с контрольной точкой до тика, список отклонённых событий пуст.
Повтор с нулевым новым временем достигает тика 121. Счётчик ресурса
сверяется с восстановленным состоянием экземпляра при входе в узел на
повторе. Хеши повторно принятого состояния и событий обеих программ
совпадают с их эталоном из нового процесса и друг с другом.

Отдельные регрессионные тесты Core проверяют одно декодирование/кодирование
для соседних нативных узлов, независимость исполнителей, чередование с
переносимыми узлами, некорректные внешние изменения перед возвратом в native
и при итоговой проверке, а также позднее отклонение публикации с повтором.
Существующие регрессии пакета ARPG покрывают частичные расписания и исходные
контроллеры перед movement. Локальные Release-наборы прошли 140 тестов Core
и 44 теста ARPG, один существующий тест Core оставался игнорируемым.
Строгий Clippy прошёл для всех целей и features этих двух пакетов.

## Воспроизведение и границы

Соберите обе версии последовательно с одинаковым примером и командой,
сохранив первую программу до сборки второй.

```powershell
cargo build --offline --locked --release -p module-engine-host --example r110_arpg
target/release/examples/r110_arpg.exe total outputs/run.json
target/release/examples/r110_arpg.exe rollback outputs/rollback.json
target/release/examples/r110_arpg.exe oracle outputs/oracle.json
```

Каждая команда требует новый путь отчёта. Запустите семь пар `total`,
чередуя порядок. Сравните хеши фикстуры, событий и принятого состояния
между версиями. Между rollback и oracle сравните `accepted_before_sha256`,
`accepted_after_sha256`, `accepted_events_sha256` и `ticks_after`. Пример
происходит от фикстуры RV-C и сохраняет её диагностические идентификаторы
`probe.rv_c4` для прямого сравнения нагрузки.

Исходные логи сборки, хеши программ, программы и отчёты сохранены локально
в `outputs/r110-arpg/`. SHA-256 базовой программы —
`8c0cf387c38aac8aa09a5a10cc17d397f35de7adf3917c34296a30ba2159fc62`.
Эти данные покрывают один headless-бой на Windows CPU. Время Linux,
частота кадров с рендером, другие ECS-бэкенды и более широкий перенос
хранилища компонентов требуют отдельных свидетельств.
