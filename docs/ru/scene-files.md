# Файлы авторских сцен

[English](../scene-files.md) | [Русский](scene-files.md) | [Документация](README.md)

## Объём и владельцы

Дополнение от 15 ноября 2026 года реализует отдельные редактируемые файлы сцен
и перестраивает Hierarchy на этой модели исходников. Ниже описаны контракт и
ограниченные проверки; локальные свидетельства находятся в
`outputs/reviews/hierarchy-scenes-20261115/`.

Core владеет полными `GameProject.scenes`, локальными ID объектов, родителями,
prefab, данными компонентов и необязательными авторскими именами. Файлового IO
сцен в нём нет. ProjectTools владеет форматом исходников, загрузкой, публикацией
и проверкой конфликтов на диске. Editor выбирает и редактирует эти документы.
Play получает отдельную загруженную копию; открытие окна не устанавливает механику.

Файлы сцен — изменяемые авторские исходники. Это **не** неизменяемые импортированные
ресурсы `AssetManifest`. Принятые хеши их байтов относятся к открытому workspace;
их нельзя переносить через авторский Undo или автоматически обновлять из Assets.

Вне объёма: streaming, одновременное редактирование нескольких сцен, родители из
других сцен, отдельные prefab-файлы, другая модель мира и новые игровые/рендер-системы.

## Точные форматы файлов

Схема графа остаётся **4**. Версия файлового контейнера задаётся отдельно:

- Прежний inline-проект: `schema_version: 4`, встроенные `game.scenes`, без
  `scene_storage_version` и без непустых внешних привязок.
- Внешний проект: `schema_version: 4`, ровно `scene_storage_version: 1`,
  `game.scene_assets` связывает постоянные ID сцен с `{ "id", "path" }`,
  а тела `game.scenes` **отсутствуют**.
- Каждый связанный файл: ровно `scene_asset_version: 1`, `scene_id`, `asset_id`
  и одна полная `scene` (`AuthoredScene`). Обе идентичности должны совпадать с проектом.

Смешение inline/внешних представлений и неподдерживаемые версии отклоняются.
Неизвестные ключи типизированных записей отклоняются; непрозрачные данные
компонентов/overrides сохраняют неизвестные пространства имён, явные null и
порядок объектов. Внутренняя сериализация истории/checkpoint/merge и IPC остаётся
полной: тела сцен вместе с привязками. Это намеренно другой формат, чем сохранение
авторского файла проекта.

`SceneAssetBinding.id` сохраняется при переносе файла и изменении отображаемого
имени. Ключ сцены остаётся целью переходов и контрактов игрового проекта. ID
объектов локальны сцене и не создаются заново при переименовании файла. Пути —
нормализованные относительные `scenes/.../*.scene.json` внутри проекта. Алиасы,
перенаправления, выход за корень, повторяющиеся ID и отсутствующие файлы вызывают
ошибку, а не замену сцены пустой.

`name` объекта — метаданные для автора. `AuthoredName` отдельно сохраняет
отсутствие поля, явный JSON null и текст. Выбор/осмотр безымянного объекта не
должен записывать выдуманное имя или override. Это не меняет `WorldObject` и
не навязывает runtime игровые данные.

## Открытие, сохранение и копирование

Открытие inline-проекта не преобразует и не записывает его. Обычный Save сохраняет
режим хранения. Новый проект, Save As и явное преобразование используют внешние
файлы сцен. Преобразование публикует принятый авторский кандидат; оно не загружает
старые байты с диска вместо несохранённых правок.

ProjectTools заранее читает каждый внешний файл в отдельный кандидат. Editor
может принять его только после проверок формата/идентичности и проверок приложения:
состав, исходники, SDK, профиль и сцены. Отсутствующий или повреждённый файл
сохраняет уже открытый проект и его состояние.

Workspace хранит принятые хеши байтов проекта/сцен (`ProjectFileState`). Перед
записью текущие байты должны совпадать с этим поколением; новые целевые пути
должны отсутствовать. Refresh не может молча принимать внешние тела или хеши.
Перезагрузка явная; Save As позволяет отдельно сохранить текущую авторскую работу.

Публикация использует сохранённые оригиналы и файловые транзакции с откатом.
DTO проекта публикуется последним. Переименование ресурса, меняющее ссылки в
сцене, включает её файл и метаданные проекта в ту же единицу отката. Неизменённые
файлы сцен не перезаписываются. Ошибка сохраняет предыдущий авторский документ,
курсор истории и принятое поколение; в `.asset-history/` могут остаться файлы
восстановления. Это не гарантия атомарности при аварийном завершении процесса
для заполненного workspace из нескольких файлов.

Save As сериализует **текущие тела из памяти**, а не старые копии файлов. Каждый Save As
в другой путь проекта создаёт отдельное поддерево сцен, в том числе повторная
подтверждённая перезапись существующей копии. Меняются пути, ID сцен/объектов/ресурсов
сохраняются. Резервный предыдущий DTO проекта продолжает ссылаться на собственные
неизменённые файлы сцен.
Последующие правки не должны менять сцены исходного проекта. Новые группы хранения
создаются независимо от отображаемого имени проекта.

## Undo, удаление и поставки

Обычные правки сцен/Undo остаются в памяти до Save. Файловые операции имеют явную
границу истории и совместно обновляют файлы с проектом. Их повтор после более
позднего успешного Save использует целевой полный снимок истории и последнее
принятое поколение диска; нельзя принимать свой Save за внешнюю правку или
ослаблять проверки неизменяемых ресурсов.

Удаление сцены сначала проверяет стартовую сцену, переходы и контракты игры.
Используемая сцена не отвязывается молча. Исходники сохраняются в корзине проекта
с идентичностью; восстановление проверяет коллизии, данные, зависимости и владение.
Ошибка или отмена сохраняет предыдущий проект.

Редактируемые Full/Team содержат настоящие авторские файлы сцен. Замороженная
архитектура Team, ограничения исходников/SDK и разрешённое авторство игры сохраняются.
Player намеренно использует запечатанную **встроенную runtime-проекцию** без внешних
авторских привязок; редактор и компилятор сцен ему не нужны. Runtime-проекция не
становится вторым редактируемым источником данных.


## Навигация редактора и Hierarchy

Используйте **File → Scene** или меню **…** рядом с текущей сценой в Hierarchy
для New, Open, Duplicate, выбора входной сцены, переименования, переноса,
удаления и преобразования. Старый inline-проект сохраняет свой режим при обычном
Save; **Convert embedded scenes to files…** — явное действие. Файловые операции
используют защиту save-first, реальный статус фоновой работы и файловый Undo/Redo.
Удаление входной сцены недоступно до выбора другой входной сцены.

Assets показывает зарегистрированные `.scene.json` отдельно от импортированных
ресурсов. Двойной щелчок открывает сцену и не добавляет её объекты в другую сцену.
Контекстные действия и область сведений работают со стабильной идентичностью.
Перенос может создать папку внутри `scenes/`; обычные Import/New folder в папках
исходных сцен отключены с объяснением. Восстановление из корзины сохраняет ID и
точные неизменённые байты исходника. Внешние правки требуют явного повторного
открытия или Save As; Refresh диагностирует их, не принимая автоматически.

В Hierarchy остаются выбор/меню текущей сцены, поиск, одна иконка Add object и
сведения о числе объектов/входной сцене. Постоянной стопки кнопок имени сцены,
дублирования и удаления и повторного заголовка нет. Строки занимают всю доступную
ширину, имеют высоту 28 логических точек и отступ детей 16. Стрелка сворачивает
настоящих детей; поиск временно раскрывает совпадения с их предками. Имя берётся
из авторского `name`, затем из ID prefab, затем `Object <id>`; движок не выводит
игровые роли сам. ID, родитель, prefab и ключи компонентов доступны в подсказке.
Выбранное имя также отображается в Inspector.

Щелчок выбирает общий для Scene/Inspector объект. **F2** или контекстное меню
открывает Rename; **Delete** удаляет объект с потомками одним проверенным Undo,
очищая существующие ссылки в этой сцене по прежнему контракту удаления. Текстовые
поля сохраняют свои клавиши. Rename имеет Apply/Cancel и проверку устаревшей сцены,
меняет только отображаемое имя и записывается при Save. Применение неизменённого
пустого имени сохраняет отсутствие/null. Play блокирует авторские правки. Поиск,
сворачивание и выбор не сохраняют, не копируют весь документ и не готовят host.
Переход к другой сцене сбрасывает выбор объекта даже при совпадении его ID.

В области высотой менее 180 логических точек поиск и Add object переносятся в **…**, строка счётчика убирается, чтобы оставить место объектам. Активный поиск помечает заголовок сцены как filtered.

Поиск/сворачивание — временное состояние вида, а не данные проекта. Аддитивная
загрузка, групповой выбор, переподчинение перетаскиванием и streaming сцен не входят
в этот этап; родитель редактируется в Inspector. Окно **Project File** явно
показывает развёрнутые данные проекта вместе с телами загруженных сцен, а не
дословный внешний DTO проекта.

групповой выбор и отдельные файлы prefab остаются за пределами этапа.
