# R3.1. Прототип редактора на Vulkan

[English](../editor-vulkan-spike.md) | [Русский](editor-vulkan-spike.md) | [Документация](README.md)

Оба painter’а рисуют корневой интерфейс текущего редактора с его стилем
в одной оболочке Win32 на winit 0.30.13 и egui-winit 0.36.2.
Изолированный проект открывает рабочее пространство Engine с
Module Blueprint и Module Library. Конструктор R2 выбирает очередь
графики и вычислений с поддержкой вывода в это окно и включает
`VK_KHR_swapchain` на том же устройстве. См. [контракт устройства R2](hardware-tiers.md#r21-device).

| Painter | Рисование и текстуры |
| --- | --- |
| [egui-ash-renderer 0.13.0](https://docs.rs/crate/egui-ash-renderer/0.13.0) | Принимает устройство Ash и командный буфер приложения, записывает отрисовку через dynamic rendering. Приложение определяет, когда вызывать загрузку и освобождение управляемых библиотекой текстур. Для пользовательских текстур можно передать совместимые наборы дескрипторов. |
| Тонкий собственный painter | Передаёт вершины и индексы egui, применяет частичные обновления текстур и записывает отрисовку с отсечением. Для буфера UNORM фрагментный шейдер умножает значения sRGBA с premultiplied alpha. |

В обоих вариантах GUI держит один кадр в обработке. Fence защищает
повторное использование буферов и текстур. Для каждого изображения
swapchain выделен свой семафор ожидания предъявления. Оба painter’а
используют прямые выделения памяти и синхронную загрузку текстур.
Сценарий в окне фиксированного размера проверяет отрисовку интерфейса.
Производственная оболочка и чтение изображений Scene и Game относятся
к [R3.2 и R3.3](product-roadmap.md#rebuild-r3).

## Воспроизведение

Запускать из соответствующего Full checkout на эталонном стенде Windows.
Нужны закреплённые Rust и DXC, реестр Cargo с зависимостями из lock-файла
и собственный каталог сборки проверки. Тонкий painter ищет DXC от
корня пакета Full. Для установленного DXC также доступна существующая
настройка `MODULE_ENGINE_DXC`.

Перед каждой серией выставить системный масштаб монитора. Держать
область 1580×940 физических пикселей видимой, без ввода и конкурирующих
сборок. Программа проверяет масштаб winit и число пикселей на точку egui
при единичном увеличении egui. Обе серии используют `IMMEDIATE`.
Перед двумя сериями укажи путь к сохранённому Release EXE в `$releaseExe`.

```powershell
cargo build --offline --locked --release --target x86_64-pc-windows-msvc -p module-engine-editor --features r31-spike
python -B scripts/verify_r31.py --exe $releaseExe --dpi 1.0 --out outputs/r31/dpi100
python -B scripts/verify_r31.py --exe $releaseExe --dpi 1.5 --out outputs/r31/dpi150
```

Перед диагностической пересборкой сохранить точный Release EXE и его
хеш. Для отдельной диагностической пары при доступном системном масштабе
использовать слой Khronos и переопределение настроек сборки ниже.
Скрипт включает проверку синхронизации и читает сообщения слоя при
запуске и завершении. Для замера он проверяет запуск Release без
диагностики Vulkan. Укажи путь к диагностическому EXE в `$validationExe`.

```powershell
cargo --config 'profile.release.package.module-engine-vulkan.debug-assertions=true' build --offline --locked --release --target x86_64-pc-windows-msvc -p module-engine-editor --features r31-spike
python -B scripts/verify_r31.py --exe $validationExe --dpi 1.0 --validation --out outputs/r31/validation
```

В каждой серии одна пробная пара и три зачётные пары с чередованием
порядка. Процесс измеряет 240 интервалов между успешными возвратами из
`vkQueuePresentKHR` после 30 кадров прогрева. Для PNG читается следующее
изображение swapchain в исходном размере, отдельно от замера. PNG и
сырые интервалы сохраняются вместе с логами процессов и SHA-256
исполняемого файла и проекта. Замер показывает темп предъявления кадров
приложением. Каждый зачётный интервал должен укладываться в `1000/60` мс,
мелкий текст должен различаться на кадрах в масштабе 1:1 при обоих
системных масштабах. Для диагностической пары требуется ноль ошибок
validation до завершения процесса. См. [критерий](bench.md#r24-culling-checks)
и [скрипт запуска](../../scripts/verify_r31.py).

## Результаты Windows — 25 ноября 2026

Зачётные прогоны выполнены на `25cfddf4c3abb545b749985ae2f9e6f65b803e57`
с digest исходников
`ad2d4f9cfda8a19f1b0951ddc8597b0a8c21e0b5faddf6e90318882b27563fdd`.
Обе серии выполнил один Release EXE с SHA-256
`c711ec8fc788c5e70a8b81eaa913f007ccfbf45f8d7e3cd95b6830a53c57de90`.
Независимая очередь проверок провела парные замеры на Windows 26H2
сборки 26300.10075, RTX 4080 SUPER с драйвером 617.42 и мониторе
144 Гц. Оба варианта использовали BGRA8 UNORM и `IMMEDIATE`.
Фактический масштаб winit и число пикселей на точку egui составили
1.0 и 1.5 при единичном увеличении egui. Граф и нагрузка
тесселяции совпадали у painter’ов внутри каждого DPI. При 100% в
одном зачётном кадре рисовалось 24 246 вершин, при 150% — 13 476.
Зачётные кадры использовали готовый атлас без загрузок текстур.

Все 2 880 зачётных интервалов уложились в `1000/60` мс.
В таблице приведены интервалы предъявления кадров приложением.
На исходных PNG 1580×940 мелкие подписи Module Blueprint и
Module Library читаются при обоих масштабах. При 150% холст
обрезает правый край узла Viewport у обоих painter’ов. Четыре
опубликованных PNG взяты из первых зачётных пар. Для каждой
комбинации painter’а и DPI хеш PNG совпал во всех трёх повторах.

При нативных 100% оба диагностических прогона подтвердили активную
проверку синхронизации Khronos и закончились с нулём предупреждений и
ошибок. SHA-256 отдельного диагностического EXE
`c0ca3f19894a3e230a0decdcaf6b67fa5fad954bae96243027c3ffbd937094a3`.
Версионированные [метрики и хеши](../evidence/r31/metrics.json)
включают каждый зачётный прогон. Полные логи, сырые интервалы и
сборки сохранены в локальных свидетельствах проверки. Поздняя правка
Clippy меняет перебор четырёхбайтовых пикселей при снятии кадра после
замера. Замеры и диагностика Vulkan выше привязаны к исходным EXE.

Преимущество по времени менялось с DPI. Для отрисовки сеток и атласа
редактора в R3.2 возьмём `egui-ash-renderer`. Устройством R2, окном,
swapchain и временем жизни кадров управляет приложение. См.
[решение о painter’е](decisions.md#r31-editor-painter).
