# Проверка одинаковых операций хостов областей

[English](../release-042-area-hosts-verification.md) | [Русский](release-042-area-hosts-verification.md) | [Документация](README.md)

Реализованный объём: у отдельного нативного хоста собственное дерево Area.
Основной и плавающий хосты используют одни меню, рекурсивную отрисовку и операции
листов. Разбиение и выбор типа остаются в адресованном хосте. Area Close удаляет
один точный лист; системный × закрывает все текущие области этого хоста.
Идентификатор нативного хоста сохраняется после закрытия исходного листа.
Команды Return в текущем UI нет. Close последней основной области недоступен;
объяснение рабочей замены показывается при наведении на недоступный Close вместо
постоянного абзаца. Явный drag docking адресуется к обоим видам хоста.

Старые плоские detached-записи читаются с прежними ID/редактором/геометрией
одиночного листа. Необязательное `tree` задаёт состав нового хоста; прежнее `id`
является стабильным ID хоста, а `editor` не служит индексом принадлежности листов.
Идентификаторы хостов и областей имеют разные пространства имён; `next_id`
выделяет оба вида, ID листов/разбиений уникальны во всех деревьях. Новые раскладки
не поддерживаются старыми бинарниками. Миграции авторского JSON или SDK нет.
Системное закрытие исходного хоста во время tear-off завершает транзакцию,
закрывает текущие области и оставляет перемещённый лист в новом хосте.
Последующий Escape не воскрешает хост. Закрытие постороннего хоста удаляет его
листы и из снимка отката.

Общий порог компактного режима — ширина 480 логических точек или высота 240
вместо прежних 800×360: обычное плавающее окно 760×510 показывает настоящее
разбиение. Ниже порога доступны активная область и переключатель. Сохранены
заголовок ОС, системный ×, нативная рамка resize и векторное меню Area справа.
SSAO, FXAA, физическое разрешение Scene 100%, проверки исходников и ограничения
Full/Team не менялись. Новых утверждений об исправлении дрожания при удерживаемом
resize, медленных физических переносах, смешанном DPI, Linux hardware,
холодном старте или FPS игры нет.

На Windows docking сначала определяет верхний видимый нативный HWND, затем
лист в его хосте. ID основного окна берётся из eframe Frame; дочерний хост
связывается с единственным HWND своего процесса, синхронно созданным для viewport,
и привязывается заново при пересоздании. Заголовок и совпавшие прямоугольники не
служат идентификаторами. Перемещаемые хост/лист исключены; оставшиеся листы
исходного хоста доступны. Постороннее или непривязанное окно, принимающее ввод указателя,
блокирует docking в скрытые области. Слой `WS_EX_LAYERED` с `WS_EX_TRANSPARENT`
пропускает мышь и исключается из поиска согласно
[Win32 hit testing слоистых окон](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows).
Нативная проба неудачного drop записала посторонний временный слой со стилем
`0x080800a8`: привязки хостов и границы листов были правильными, но прежний поиск
останавливался на этом пропускающем ввод слое. Точный процесс не установлен.
Правка исключает только сочетание layered и transparent; обычные непрозрачные
перекрывающие окна по-прежнему блокируют скрытые цели. Исходный слот отдельно обеспечивает быстрый
перенос наружу и обратно. При неоднозначной разнице HWND во время создания
идентификатор не угадывается; docking ждёт корректной привязки. Новых зависимостей
и суффиксов заголовка нет.
