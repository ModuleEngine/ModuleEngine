# Поддержка UI редактора навыками

[English](../editor-ui-skills.md) | [Русский](editor-ui-skills.md) | [Документация](README.md)

Два навыка поддерживают [дизайн редактора](editor-ui-design.md) и
[техническую базу](editor-ui-spec.md). Они относятся к нативному редактору
ModuleEngine, а не игровому HUD или посторонним приложениям. Они читают текущие
контракты репозитория вместо второй встроенной копии всей дизайн-системы.

Для конкретного окна/диалога использовать [полный каталог интерфейсов](editor-ui-catalog.md),
на который ссылаются общий дизайн/спецификация. Его требования и листы состояний
входят в ревью; одна схема не подтверждает полное покрытие. Эта поставка каталога
не меняет установленные инструкции навыков.

## Навыки и вызов

| Навык | Назначение | Поддерживаемый исходник |
| --- | --- | --- |
| `$moduleengine-ui-design` | Спроектировать маршрут задачи или реализовать явно разрешённую часть UI с общими размерами и правилами сохранности. | [SKILL.md](../skills/moduleengine-ui-design/SKILL.md), [русская инструкция](../skills/moduleengine-ui-design/references/SKILL.ru.md) |
| `$moduleengine-ui-review` | Проверить задачу, внешний вид, ввод, права, сохранность и границы настоящих доказательств. | [SKILL.md](../skills/moduleengine-ui-review/SKILL.md), [русская инструкция](../skills/moduleengine-ui-review/references/SKILL.ru.md) |

Пример запроса на дизайн:

```text
$moduleengine-ui-design Предложи панель иконок Scene и справку при наведении/фокусе.
Обнови только дизайн; редактор пока не реализовывай.
```

Пример запроса на реализацию, только когда она действительно нужна:

```text
$moduleengine-ui-design Реализуй только согласованные иконки Play/Stop/Save.
Сохрани существующие команды/клавиши и проверь поведение и подсказки.
```

Пример запроса на ревью:

```text
$moduleengine-ui-review Проверь эту правку UI по задаче и дизайн-базе.
Только чтение; отдели подтверждённые ошибки от отсутствия нативных доказательств.
```

Обычное автоматическое обнаружение навыков остаётся включено; явный вызов удобен,
когда нужен конкретный метод. Навыки не разрешают реализацию из обсуждения и
не отменяют текущие указания пользователя. Ревью автора реализации — самопроверка;
существенным изменениям по-прежнему нужен отдельный проверяющий по
[контракту ревью](review.md).

## Установка и сопровождение

Папки `docs/skills/` в репозитории — канонические исходники поставки, а не
вторая автоматически обнаруживаемая установка проекта. Пользовательские копии
размещаются в `$CODEX_HOME/skills/<skill-name>/`, обычно
`~/.codex/skills/<skill-name>/`. В каждой: `SKILL.md`, `agents/openai.yaml` и
`references/SKILL.ru.md`. Пути репозитория в инструкциях разрешаются от
проверенного корня ModuleEngine, а не папки навыка. Инструкции не привязаны к
букве диска этой машины.

При изменении навыка обновить полный русский вариант и при необходимости UI-
метаданные; проверить каноническую папку через `scripts/quick_validate.py` из
skill-creator. Это проверка структуры/frontmatter, а не поведения. Существенные
правки проверить на реалистичных исходных запросах до объявления метода полезным.
Скопировать проверенные файлы в соответствующий пользовательский навык и
сравнить хеши; посторонние правки пользователя сохранять, не перезаписывая
неожиданную установку. Зависимость runtime не добавляется.

Доказательства поставки, включая хеши установленных файлов и независимое ревью,
хранятся в `outputs/reviews/editor-ui-design-20261114/`. Проверка файловой системы
не устанавливает, обновился ли список навыков уже открытого приложения. Установка
навыков не означает нового поведения нативного UI или приёмки этапов реализации.
