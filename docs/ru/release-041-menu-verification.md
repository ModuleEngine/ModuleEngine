## Полученное поведение

Project Settings содержит навигацию по разделам, строки подпись/значение, справку по запросу и свёрнутые условия. В широкой панели разделы находятся слева; в узкой сохранён доступ с клавиатуры. Постоянные поясняющие абзацы убраны. Несохранённые изменения, подготовка и ошибки с доступным действием имеют краткую обратную связь; дополнительного Apply поверх существующего немедленного коммита нет.

Custom Rust может читать разрешённую настройку по стабильному ID, перечислять ID и подписи вариантов, узнавать действующий выбор и запрашивать другой вариант. Игра выдаёт собственные описания панелей и Choice; один нативный адаптер отображает их в Player и Game viewport редактора. Пример привязывает `antialiasing` через `custom_sources["settings-menu"]`. Скрипт не содержит ID прохода рендера или повторного списка команд FXAA/Off. См. [API и полный пример](custom-rust.md#script-settings-menu).

Необязательное `game.player_preferences.namespace` задаёт постоянную идентичность игры. Допустимый личный выбор перекрывает raw-команды времени выполнения и условия/начальные значения Project для своей группы. Остальные группы сохраняют прежнее поведение. Для привязки доступны только однозначные полные варианты параметров/включения с исключительными целями; удалённые или неподдерживаемые настройки скрывают элементы управления. Неоднозначные действующие controls показываются как Runtime controlled.

Предпочтения используют существующий сервис JSON-хранения с отдельным владельцем Host. Недопустимый запрос сохраняет принятое состояние. Поздний отказ тика откатывает настройки, меню, оба экземпляра Custom и мир до записи. Недоступный сохранённый вариант заменяется текущим допустимым выбором Project без перезаписи сохранения. Повреждённые, будущие и некорректные payload сохраняются без изменений в режиме только чтения. Ошибка записи оставляет принятый выбор активным и явно показывает Not saved. Неизвестные поля сохранённого payload сохраняются.

Принятый выбор и показанные пиксели имеют отдельное происхождение. Applying остаётся видимым до публикации настоящего кадра с принятым выбором. Ошибка рендера остаётся видимой, а корректное меню позволяет запросить восстановление. Ввод popup ограничен Game viewport, в том числе при уменьшении области с уже открытым списком; жест закрытия не передаётся в игровой мир.

Новые поля требуют точной идентичности SDK `module-engine-data-api/v3`. Старые проекты и пакеты v2 не перепривязываются и не переименовываются молча. Нужны совпадающие исходники/SDK и существующий явный путь обновления контрактов. Предыдущая поставка сохраняет собственные бинарники и pins. Версия бинарника/пакета 0.4.0 не изменена.

## Артефакты и проверки

Готовые launchers и редактируемый пример находятся в [`outputs/release-041-menu`](../../outputs/release-041-menu): `launch-team.cmd`, `launch-full.cmd`, `launch-player.cmd` и `launch-clean-profile.cmd`. Доступны [карта владельца](../../outputs/release-041-menu/owner-card.ru.md), [короткий пример привязки](../../outputs/release-041-menu/binding-example.md) и [сравнение кадров](../../outputs/release-041-menu/comparison.html). `menu.rs` рядом с примером — читаемая копия; главным является встроенный источник Custom.

Для редактирования Custom в Team нужны закреплённые Rust/Cargo и системные linker/SDK. В стандартном Cargo cache этой машины нет `sha2`; неуспешный экспорт с ним сохранён в `work/release-041-menu/export-team-player.*`. Launchers Full/Team выбирают уже подготовленный offline cache рабочего каталога, только если `CARGO_HOME` не задан. Настоящий экспорт Team с этим cache проходит через собственный `.sdk` при запрещённом редактировании Engine. Player не компилирует исходники Rust. Это не подтверждение переносимости toolchain на чистую машину.

Главный Player начинает чистый профиль с FXAA. Настоящий клик egui выдаёт адресованный ввод запечатанному Custom worker; Off принимается и сохраняется. Новый процесс Player читает Off, а другой чистый профиль — FXAA. Перенос пакета сохраняет выбор. В одинаковой сцене 960×540 через Vulkan / NVIDIA GeForce RTX 4080 SUPER между FXAA и Off меняются 3 246 пикселей. Off после перезапуска побайтно совпадает с выбранным Off; FXAA чистого профиля побайтно совпадает с исходным FXAA.

Настоящая блокировка совместного доступа Windows запрещает замену сохранения после загрузки допустимого FXAA: Off остаётся активным и видимо несохранённым, всё прежнее дерево сохранения не меняется, а новый процесс возвращается к сохранённому FXAA. Отдельные повреждённые/будущие/некорректные профили тоже принимают несохранённый Off, не изменяя свои байты. Недоступные сохранённые варианты заменяются FXAA без изменения payload. Хеши полных деревьев подтверждают неизменность авторского примера и главного/перенесённого пакетов Player. Player из Team также сохраняет Off в том же профиле и принимает настоящий выбор меню в отдельном профиле. Отдельный fixture меняет только заголовок панели Custom на My display, экспортируется через собственный SDK Team и показывает этот заголовок в полученном Player; пиксели принятого/сохранённого Off точно совпадают с исходным Off. Оригинальный проект Team не изменён. Изменение определения доступного варианта отклоняется замороженной границей Team.

Обычные снимки Editor получены через WGPU/Dx12 на той же RTX 4080 SUPER: [Team](../../outputs/release-041-menu/team-settings.png), [Full](../../outputs/release-041-menu/full-settings.png). Они показывают компактные поля при настоящей начальной подготовке сцены и несохранённой индексации assets, а не заявленное состояние покоя/полной готовности. [Отчёт нативного Player](../../outputs/release-041-menu/native-player/native-frame-report.json) завершает стандартный прогон со 120 новыми кадрами в GPU, 30 прогревочными callbacks и без ошибочных кадров. `target_met:false` указан явно: нейтральный пример без врагов не сертифицирует целевую производительность ARPG.

Computer Use дополнительно показал FXAA в обычном поставленном Player; после клика Off наблюдались Off, изменённые кромки и отсутствие статусов Applying/Not saved. После закрытия и нового запуска другая плавающая панель перекрыла меню; это оконное наблюдение меню после перезапуска не засчитывается. Выбор/пиксели после перезапуска подтверждены отдельными процессными проверками выше. [Оконный receipt](../../outputs/release-041-menu/window-ui-receipt.json) фиксирует ограничение. Сессия Computer Use сброшена; постороннее содержимое не управлялось, его screenshot payload не копировался в артефакты.

Эти прогоны используют настоящий адаптер меню, Custom IPC пакета и нативные пиксели. Ограниченная диагностика не подразумевает снимок рабочего стола или участие человека. Начальные неуспешные UI fixtures и подтверждённые регрессии popup оставлены в логах; доказательствами приёмки являются только последующие успешные проверки.
