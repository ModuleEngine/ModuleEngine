# Локальная очередь проверок на Windows

[English](../local-queue.md) | [Русский](local-queue.md) | [Документация](README.md)

На общем проверочном ПК с Windows используйте очередь для сборок тестов
Cargo, сборок Release, GPU-проверок, нативных окон, захватов и бенчмарков.
В группе gpu одновременно выполняется одна задача. Группа light выполняет
до двух задач и предназначена для проверок чтением, которые обходятся
без сборки и окна. Использование рабочего стола и конкурирующие нагрузки
согласуйте с владельцем стенда. Очередь даёт автору и координатору пакета
свидетельства проверок. Существенные изменения по-прежнему требуют
[независимого ревью](review.md) и подходящих [профилей](verification.md).

## Подача заявки и получение результата

В PowerShell 7.5 или новее передайте абсолютный путь к checkout автора и полный
SHA его зафиксированного HEAD. Используйте одобренную владельцем версию
очереди. Установленная версия доступна из любого worktree, включая ветки,
созданные до попадания скриптов в main.

```powershell
$queue = 'E:\ModuleEngine-queue\releases\<approved-commit>\scripts\queue'
$checkout = (Get-Location).Path
$sha = git -C $checkout rev-parse HEAD
$id = & "$queue\submit.ps1" -Worktree $checkout -Commit $sha -Check render -Author R2

# Сохраните ID и продолжите работу. Позже, из любого checkout:
& "$queue\result.ps1" -Id $id
& "$queue\result.ps1" -Id $id -FullLog
```

Скрипт подачи печатает числовой ID Pueue в stdout. Связанный worktree в
каталоге очереди закрепляет коммит. Демон разворачивает его внутри выбранного
слота. Автор может сразу редактировать файлы, менять ветки и создавать
коммиты в своём checkout. Общий Git-репозиторий и регистрация worktree очереди
должны оставаться доступными до завершения задачи. Подготовленные в индексе,
изменённые, неотслеживаемые и игнорируемые файлы автора остаются в исходном
checkout. Сначала закоммитьте необходимые исходники или фикстуры. Для отдельно
установленных инструментов и внешних ресурсов используйте согласованные
входные данные стенда.

Установленный [список разрешённых проверок](../../scripts/queue/checks.json)
задаёт команды, группы, таймауты и артефакты. При подаче можно выбрать имя
проверки и группу. В light допускаются только проверки с группой light
в списке. Их можно повысить до gpu. Когда этапу нужна другая команда или
фикстура, расширьте список через ревью. Подавайте заявки и повторы через
обёртку. Прямое создание или редактирование задач Pueue, немедленный запуск
и изменение приоритета обходят эти правила. Очередь рассчитана на доверенных
авторов и зафиксированный код в одной учётной записи с правами демона Windows.

| Проверка | Группа | Свидетельство |
| --- | --- | --- |
| roadmap | light | Установленный валидатор читает обе версии карты и шаблоны из снимка. |
| format | gpu | Проверка форматирования workspace. |
| quick, contracts, clippy, native, package | gpu | Указанный профиль в его собственных границах, с логами и отчётами. |
| render | gpu | Offscreen-профиль с обязательными возможностями, проверками retained Host и Vulkan. |
| window-graph | gpu | Графический тест Player в Release и нативном окне с выбранным адаптером и режимом показа. |
| bench-once | gpu | Диагностический проход S1–S5 с артефактами бенчмарка. Повторяемость по трём прогонам и приёмка требуют отдельных свидетельств. |
| queue-probe | gpu | Короткая диагностика порядка и сеанса Windows. Рендерер не запускается. |

Результаты сохраняются в **E:\ModuleEngine-queue\results\<id>**. При передаче
результата укажите ID, полный коммит, дайджест исходников, статус, условия и
путь к отчёту. В **report.json** записываются запрошенный и наблюдавшийся
SHA, дайджесты до и после, время, команды, итог, код выхода и окружение.
В **log.txt** целиком сохраняются stdout и stderr проверки. Обёртка при
необходимости ждёт этот ID, выводит отчёт и последние 50 строк. В
**artifacts/** остаются результаты, заявленные маршрутом. Ошибка, таймаут
и несовпадение коммита дают ненулевой код выхода. После прерывания демоном
или ОС могут остаться только заявка, часть лога и конечный статус Pueue.
Сохраните эти материалы и подайте заявку заново, чтобы получить новый ID.

Побайтовая опись покрывает отслеживаемые файлы и неигнорируемые
неотслеживаемые исходники согласно [контракту независимого
ревью](review.md#привязка-к-исходникам). Очередь проверяет свой checkout до
и после команды. У игнорируемых результатов сборки и установленных
инструментов отдельные сведения о происхождении. Настроенный таймаут
относится к командам после разворачивания снимка и подготовки окружения.
Задание Windows включает дочерние процессы, ждёт их выхода и завершает
всё дерево при таймауте.

Маршрутам с окном нужен разблокированный интерактивный рабочий стол
вошедшего пользователя. Сохраняйте его доступным до завершения задачи.
Название адаптера берётся из собственных артефактов проверки, если
маршрут его сообщает. Список видеоустройств ОС показывает установленные
версии драйверов. Для определения выбранного адаптера нужны данные самой
проверки. Отчёт различает сопоставленные физические адаптеры PCI,
программные рендереры вроде WARP или llvmpipe и неподтверждённые
сопоставления. Прежде чем делать вывод о физическом GPU, времени,
выводе на экран или аппаратном Linux, проверьте условия и артефакты маршрута.

## Настройка и обслуживание стенда

Владелец один раз настраивает отдельную очередь на проверочном ПК.
Установите [Pueue/Pueued 4.0.4](https://github.com/Nukesor/pueue/releases/tag/v4.0.4)
для текущей учётной записи, сверьте SHA-256 релиза и разместите оба
исполняемых файла в каталоге bin очереди или в PATH. Установите
PowerShell 7.5+, Git, Python 3.9.17+ и
[зафиксированные Rust и нативные инструменты Windows](verification.md#запуск-и-окружение).
Задачи используют системный и пользовательский PATH и офлайн-кэш Cargo
текущей учётной записи. Для графических маршрутов владелец может
разместить зафиксированный Windows DXC и его DLL в каталоге bin очереди.
Сверьте их хеши с манифестом инструментария проекта. Входные данные
бенчмарков определены в [контракте S1–S5](bench.md).

Из проверенного коммита опубликуйте отдельную копию клиента и исполнителя.
Сохраняйте путь и содержимое каталога версии, пока на него ссылаются заявки.

```powershell
$root = 'E:\ModuleEngine-queue'
$release = git rev-parse HEAD
$bundle = Join-Path $root "$release.zip"
$install = Join-Path $root "releases\$release"
git archive --format=zip --output=$bundle $release scripts/queue scripts/review_snapshot.py site/roadmap_map.py site/roadmap_events.py
Expand-Archive -LiteralPath $bundle -DestinationPath $install
& "$install\scripts\queue\setup.ps1" -Python 'C:\path\to\python.exe' -RegisterAutostart
```

Setup использует отдельную loopback-конфигурацию, состояние и логи под
каталогом очереди и TCP-порт 16924. Он устанавливает gpu=1 и light=2.
При занятом порте укажите свободный **-Port** при первичной настройке.
**-RegisterAutostart** регистрирует задачу входа текущего пользователя
с интерактивным токеном. Запуск из Планировщика задач проверяет
регистрацию без перезагрузки Windows. Для работы без автозапуска
выполните **pueued --config E:\ModuleEngine-queue\pueue.yml** в отдельном
PowerShell интерактивной учётной записи и снова запустите setup.
Сторонняя установка Pueue использует собственную конфигурацию.

```powershell
$pueue = 'E:\ModuleEngine-queue\bin\pueue.exe'
$config = 'E:\ModuleEngine-queue\pueue.yml'
& $pueue --config $config status --group gpu
& $pueue --config $config pause --group gpu --wait
& $pueue --config $config start --group gpu
```

В версии 4.0.4 команда **pause --group gpu --wait** приостанавливает
планирование и даёт текущей задаче закончиться. Без **--wait** команда
приостанавливает и выполняющийся процесс. Перед плановой перезагрузкой
или обслуживанием демона приостановите нужные группы и дождитесь выхода
текущих задач. Ожидающие заявки сохраняются в отдельном каталоге состояния.
После входа проверьте ожидаемые ID и состояние групп до возобновления.
Перезапуск демона и перезагрузка Windows проверяются отдельно. Подайте новую
заявку для повторения прерванной проверки, чтобы сохранить прежний номер
и свидетельства. Избегайте **pueue restart**, **reset** и **clean** для
этой очереди. Обёртка связывает каждый ID с его исходной заявкой.

Храните каталоги результатов и точные EXE или пакеты, на которые опирается
принятая проверка. Промежуточные сборки, включая Cargo target, находятся
в снимке очереди. После приёмки сохраните и сверьте хеши нужных артефактов
вне снимка, дождитесь выхода принадлежащих ему процессов, сверьте
зарегистрированный путь с отчётом и удаляйте только этот снимок через
**git worktree remove** из его Git-репозитория. Незавершённой заявке по-прежнему
нужен зарегистрированный checkout. Сохраняйте материалы незакрытых ошибок.
