# Внедрение нативного UI редактора — этап 2A

[English](../editor-ui-rollout.md) | [Русский](editor-ui-rollout.md) | [Документация](README.md)

Нативный UI, порученный 15 ноября 2026 года, внедрён и поставлен. Для 18 задач
[этапа 2A](editor-clarity-plan.md#stage-2a) есть рабочие маршруты и проверки в
ограниченном объёме Windows/WSLg. **Это не полная сертификация физических DPI,
ввода из активного окна или новой производительности Player.** Границы перечислены
ниже. За этапами 3/5/6 остаются настройки рендера/подсистем и карта; G2 не начат.

## Что изменилось и как пользоваться

- Начинай разбор состава с **Engine → Windows → Composition → Engine Overview**.
  Группы, список и детали отделяют технические системы, переиспользуемый gameplay
  и содержимое конкретной игры. Наличие, участие, права и готовность различаются;
  обновление кешированных сведений обозначено. Действия открывают реальные цели.
- Engine/Project — защищённые раскладки в границах прежних прав пакета.
  **+** создаёт именованную копию текущей раскладки. Свои вкладки можно переименовать
  и удалить; сброс требует подтверждения и относится к выбранной раскладке.
  Прежние персональные раскладки сохранены. Ошибка загрузки сохраняет активную
  раскладку и блокирует перезапись повреждённых данных.
- **Area** или ПКМ по разделителю области открывают split/join/move. Меню называет
  и подсвечивает сохраняемого соседа. Вынесенная область — настоящее окно ОС с
  общими документом, историей и Game-сессией. Закрытие убирает только этот экземпляр; явный Return сохраняет его ID.
  В компактном главном окне **Area → Focus area** сохраняет остальные области.
- В графах работают СКМ/ПКМ-перетаскивание, обычное колесо вокруг указателя,
  ПКМ-действия, Shift+F10, двойной клик по раскрываемым узлам, F, Alt+ЛКМ для
  удаления связи и смешанное выделение/Delete. Добавление/удаление — одна
  транзакция Undo с очисткой настроек рендера. Выбирается ближайший видимый пин;
  Alt не создаёт связь. Постоянная строка Add/Open/Frame/Delete убрана. Палитра
  называет свою область; справка пина локальна, общий справочник типов свёрнут.
- В Scene — непрозрачные инструменты трансформации/осей/snap/frame с понятными
  векторными иконками. Они забирают выбор, камеру и drop; уже начатый жест
  сохраняет владельца при пересечении overlay. World/local, привязка и один жест/
  один Undo сохраняются.
- Inspector группирует объект/prefab, Transform, владельца и локальные черновики.
  В Assets есть иконки папок, выделение, выделяемый адрес только для чтения/
  breadcrumbs, копирование путей/ссылок и компактные Details. Файловые транзакции
  и ID сохраняют прежний контракт. Короткие области используют прокрутку или
  компактные инструменты.
- Постоянные Play/Pause/Stop/Restart/Save находятся в общей оболочке. Game показывает
  viewport/HUD/фокус/статус; legacy Reset остаётся отдельным действием. Остальные
  инструменты используют группы, перенос и прокрутку. У Rust/Blueprint есть
  компактное переключение Inspector, HLSL открывает настоящих потребителей,
  History сохраняет отдельные checkpoint/merge. Для отсутствующего Rust source
  выводится пояснение, а Apply без действия не показывается.

Стандартные элементы имеют смысловые имена, checked/disabled-состояния, справку
о клавишах/причинах при наведении и фокусе, общие отступы/шрифты/поверхности в
логических точках. Вкладка не выдаёт права Engine. Team сохраняет редактирование
Project и заблокированный Engine; сам Engine Overview по-прежнему требует Full
и совпадающие исходники.

Персональное состояние использует отдельный `workspaces.json` и прежние форматы
раскладок версий 1/2. Черновики не входят в раскладку. Миграция авторского документа/
схемы, новая игровая механика, нативная зависимость или сервис платформы не добавлены.

## Безопасность черновиков и исходников

Черновики Inspector объекта переживают выбор и Apply другого компонента;
конфликт схемы/источника требует явного Discard. JSON параметров нод принадлежит
документу и привязан к стабильным ID графа/ноды, общий для встроенных, вынесенных
и скрытых областей. Чистый текст следует за данными; черновик переживает выбор и
конфликт. Apply создаёт один шаг истории, неизменённое значение — ни одного.
Save/export/Play и защищённые переходы учитывают скрытые черновики. Замена/
удаление модулей и Undo требуют разрешить черновик параметров. Cancel сохраняет
текст и авторские данные. Принятие нового документа очищает прежний кэш черновиков.

В Full inventory и регрессии пропущенных файлов включены новые UI-исходники,
в том числе `node_drafts.rs`. Раскладка не разрешает authoring без исходников.
Авторский проект, SDK, привязки, Recent и прежние раскладки побайтно совпадают с
зафиксированным началом; прежняя посторонняя работа сохранена. Для новых
исходников обновлён только канонический манифест Full.

## Исправления, найденные проверками

Независимые ревью и реальные UI-тесты нашли и исправили ложную подпись prefab,
повторное открытие справки после Escape, отсутствие признака обновления кеша,
сброс неверной раскладки, миграцию legacy-типа и возврат из глубокого дерева окон.
В графах исправлены Add/history, удаление выбранной связи перед bypass,
цель клавиатурного меню, фокус тела ноды, плотные/обрезанные пины и конфликт Alt
на малом масштабе. В Scene — компактные/disabled overlays и продолжение жеста камеры.

Интеграционное ревью также обнаружило прежнюю потерю черновиков параметров нод.
Тесты с настоящими событиями указателя/клавиатуры проверяют выбор, Save/отчёт,
export/Cancel, Apply/Undo/Redo, conflict/Discard и точные сохранённые байты.

Нативный benchmark с прежним лимитом 45 секунд выявил прежний дефект reuse Custom:
метаданные Core используют литеральный `CARGO_PKG_NAME`, а аудит SDK допускал лишь
`CARGO_PKG_VERSION`. Для обоих уже есть точная проверка происхождения по манифесту/
метаданным Cargo. Аудит теперь допускает эти два литерала; неизвестное окружение SDK
и вычисляемые аргументы по-прежнему не кешируются. Контроль выявляет старую ошибку;
12 freshness-регрессий и реальные coalescing/independent-state/eviction проходят.
Fingerprint, проверка исходников и критерий готовности не обходятся. Отдельный
сбой MSVC в TEMP песочницы сохранён в доказательствах; отдельный TEMP в workspace
исправляет пробу окружения, но сам не исправлял аудит макросов.

WGPU painter непосредственных viewport закреплённой версии eframe не передаёт
запросы снимков дочернего окна. Неработающий помощник удалён. Проверка Windows
PrintWindow собственного окна подтверждает геометрию/gizmo/overlays Scene;
снимки главного окна сохраняют прежний диагностический маршрут. В обычный рендер
не добавлены readback или очередь снимков. Computer Use не включался.

## Измеренная отзывчивость и оставшиеся границы

Нативный benchmark F23 с Graph/Game/Scene завершил 90 stopped-pan и 90 play-pan
измерений, проверил продвижение симуляции, сохранение владельцев и нового
приостановленного worker с нулевым временем после Stop без ошибок:
**27,1335 с всего**, в прежнем watchdog 45 секунд. Использованы события фокуса/
указателя egui; нативный фокус записан отдельно. Это не проверка физического ввода.

| Фаза | Editor callback mean / p95 | Callback interval mean / p95 |
| --- | --- | --- |
| Stop + pan графа | 12,4247 / 15,4082 мс | 16,4193 / 19,3164 мс |
| Play + pan графа | 14,0011 / 17,4396 мс | 18,0926 / 21,5283 мс |

Два запуска до UI завершили те же фазы 90/90, но не дождались финального Stop
из-за некешируемой подготовки; полными успешными benchmark они не стали. Их
callback mean/p95: 12,1664–12,5524 / 15,3288–15,5400 мс в Stop и
16,0520–16,4618 / 20,1676–20,6954 мс в Play. Новые данные не показывают крупной
регрессии UI и дают меньшее время callback в Play, но короткая выборка и
неконтролируемая фоновая нагрузка не доказывают причинное ускорение. Этот сценарий
трёх областей Editor не заменяет прежний критерий самостоятельного G1/ARPG 60 FPS,
холодный старт или новую сертификацию производительности рендера.

Доступен один монитор 3440×1440 с физическим DPI 96. Физические 150/200%, переходы
между разными DPI, выбор в нативных picker и внешний keyboard/mouse-to-display QA
в активном окне не проверены. Для логического масштаба и чистых контрактов фокуса/
Cancel/ввода есть отдельные проверки; они их не подменяют. Отсутствие нативных
аудио/picker Linux и ограничения аппаратного Linux сохраняются. Ранний снимок Scene
авторского проекта показывает подготовку, а не готовую геометрию. [Матрица 72 строк](../editor-ui-coverage.json)
фиксирует 68 реализованных поверхностей, три явно отложенных маршрута V02/V10/D11
и контракт регистрации P22. Это не 72 отдельных окна и не сертификация всех
нативных состояний.

## Дополнение хранения сцен и Hierarchy

Последующая [реализация файлов сцен](scene-files.md) заменяет прежнюю стопку
кнопок Hierarchy, вводит изменяемые исходники сцен и добавляет D13/D14. Исходная
матрица stage2A содержала 72 записи; текущий каталог содержит 74. Её проверки
сохраняют исходную привязку, а дополнение отдельно фиксирует файловые/UI/package
проверки и независимое финальное ревью.
