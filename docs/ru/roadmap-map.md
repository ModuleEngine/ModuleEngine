# Визуальная дорожная карта

[English](../roadmap-map.md) | [Русский](roadmap-map.md) | [Документация](README.md)

Визуальная дорожная карта — HTML-страница с картой фаз [трека перестройки движка](product-roadmap.md#rebuild), текущей задачей, ближайшими шагами и примерными сроками. Она собирается автоматически из [docs/ru/product-roadmap.md](product-roadmap.md) и английской версии; статусы задач в самой странице вручную никто не правит.

## Где смотреть

После каждого слияния в `main`, которое затрагивает дорожную карту, [workflow Roadmap map](../../.github/workflows/roadmap.yml) публикует страницу на GitHub Pages: `https://myjname.github.io/ModuleEngine/`. Тот же workflow публикует рядом [карту походов](#карта-походов): `https://myjname.github.io/ModuleEngine/world/`.

Однократная настройка: в репозитории **Settings → Pages → Build and deployment** выберите в **Source** вариант **GitHub Actions**. До этого задание публикации падает, а сборка и проверка всё равно выполняются.

## Как поменять статус

Последний столбец каждой таблицы задач фазы — статус:

| Значение в английской таблице | Значение в русской таблице | Что видно на карте |
| --- | --- | --- |
| `Done` | `Сделано` (также `Выполнено` или `Готово`) | Задача готова |
| `In progress`, можно `In progress (2–3 d)` | `В работе`, можно `В работе (2–3 д)` | Задача в работе |
| Оценка, например `2–3 d` или `1.5 w` | Оценка, например `2–3 д` или `1,5 н` | Не начата |
| `Optional · 2–3 d` (перед оценкой) | `Необязательно · 2–3 д` | Отслеживается как обычная задача, но фаза и зависящие от неё контрольные точки завершаются без неё. Префикс нужен в обеих таблицах |

Переходы статусов ведёт отдельный чат дорожной карты. Чаты реализации передают принятые результаты и свидетельства проверок, а технические контракты обновляют в своих pull request. Когда переход готов, планирующий чат сверяет `main` с рабочими чатами и предлагает один PR статусов для подтверждённых завершений и фактически начатых работ. Применяйте предложение в отдельном чате дорожной карты и меняйте обе языковые таблицы вместе. При переводе задачи в работу сохраняйте исходную оценку в скобках, если она ещё применима.

Из этих статусов выводятся цвет фазы, карточки «Сделано / Сейчас / Дальше», полоса прогресса, метка в шапке и заголовки столбцов:

- фаза готова, когда выполнены все её обязательные задачи. Иначе она считается текущей, если выполнена хотя бы одна обязательная задача или любая задача находится в работе;
- фаза следующая, когда все фазы, от которых она зависит, готовы или текущие;
- контрольная точка (R1+R3+R4, R2+R5) пройдена, когда готовы все её фазы, включая фазу, стрелка от которой нарисована через другую (R1 через R4);
- в шапке показана задача в работе, а если её нет — следующая доступная; когда готовы все задачи, шапка сообщает о завершении трека, а когда незавершённые задачи есть, но ни одна фаза не может начаться (например, зависимость удалена из плана), — о блокировке и о том, чего ждёт фаза.

Читаются только разделы с заголовком вида `### <ID> — <название>` (например, `### R1 — ...` или `### AI-A — ...`) и строки задач, чей ID начинается с ID фазы (`R1.3`, `AI-A.0`).

## Что остаётся ручным

Шаблон страницы [scripts/roadmap_map.html](../../scripts/roadmap_map.html) содержит русские формулировки: короткие названия задач, описания фаз, зависимости, раскладку карты, шкалу сроков и маршрут версий. Для задачи, которой ещё нет в шаблоне, страница берёт первое предложение задачи из русской дорожной карты. Новой фазе нужен узел в шаблоне (`phases` и `pos`) и стрелка для каждой её зависимости (`add('откуда>куда', ...)`); пока узла нет, сборка выводит предупреждение, а фаза не показывается. Фаза, удалённая из дорожной карты, сохраняет узел, но теряет задачи и помечается «нет в плане»; старые задачи из шаблона не возвращаются.

`scripts/test_roadmap_map.py` запускает модель данных обеих страниц в Node.js и проверяет на небольших EN/RU-фикстурах, что фаза, удалённая из обеих версий Markdown, исчезает с карты, а шапка сообщает о блокировке, что точке 0.5 нужны R1, R3 и R4, и что у каждой зависимости из карточки фазы есть стрелка. Проверки по живой дорожной карте выводят ожидания из её таблиц, поэтому обычная правка плана их не ломает.

## Карта походов

Карта походов — та же дорожная карта в виде игровой пиксельной карты, собранная из тех же таблиц. Каждая фаза (R0–R10) — область со своей темой, каждая задача — провинция внутри неё, а стрелки показывают, какая фаза открывает какую. Контрольные точки и рубежи версий — острова с маяками, ветка ИИ — башни магов.

| Статус задачи | На карте |
| --- | --- |
| `Сделано` | Захвачена: яркие цвета, золотая граница, синий флаг. Фаза, где выполнены все обязательные задачи, отмечена короной |
| `В работе` | Под осадой: анимированная огненная рамка, лагерь и костёр |
| Не начата, первая в начатой фазе | Следующий ход: жёлтый вымпел и палатка. Показывается, пока в этой фазе ничего не в работе |
| Не начата, любая другая | Туман войны: чем дальше от фронта, тем гуще |

Наведите курсор на провинцию, чтобы увидеть название и статус; клик открывает критерий приёмки и оценку, клик по ленте области — цель фазы и список её провинций. Названия и критерии задач берутся из русской дорожной карты, карточка показывает полный текст ячеек задачи и критерия; английская таблица даёт только статусы. Задача, которая ждёт задачу другой фазы (R2.3 ждёт R1.6), не предлагается как следующий ход, пока та не выполнена. Эти зависимости объявлены в `TASK_DEPS` шаблона; если ждущая задача есть в дорожной карте, а задачи, которую она ждёт, нет, сборка (включая `--check`) падает и называет обе задачи.

Страница — статический файл без доступа к сети: Content-Security-Policy блокирует любые запросы. Вся графика рисуется кодом на canvas, внешних ресурсов нет. Анимация отключается при `prefers-reduced-motion`.

Вручную поддерживается [scripts/roadmap_world.html](../../scripts/roadmap_world.html): названия и темы областей, положение каждой области и вехи, а также `STATIC` с зависимостями и целями каждой фазы. `STATIC` повторяет `phases` страницы-таблицы, а `scripts/test_roadmap_map.py` падает, если они расходятся. Провинции раскладываются автоматически по порядку задач, поэтому новая задача не требует правки шаблона. Новой фазе нужна запись в `STATIC` и `REGS`; пока её нет, сборка выводит предупреждение, а фаза не показывается. Фаза, удалённая из дорожной карты, исчезает с карты вместе со своими стрелками.

### Живая активность GitHub

При сборке `scripts/roadmap_events.py` читает через API GitHub активность репозитория за последние 14 дней, используя собственный `GITHUB_TOKEN` workflow, а карта показывает её объектами в местах, на которые ссылаются события. Задача вроде `R2.3` в заголовке, сообщении коммита или имени ветки указывает на свою провинцию. Задача ИИ вроде `AI-A.2` указывает на башню своей фазы. Фаза вроде `R2` помещает событие в свою область, а событие без ссылки уходит на текущий фронт:

| Событие | На карте |
| --- | --- |
| Коммит | Маленький флажок рядом с провинцией |
| Открытый pull request | Корабль плывёт к провинции от ближайшего моря |
| Влитый pull request | Корабль с золотым флагом в порту, с искрами |
| Комментарий | Птица кружит над провинцией |
| Комментарий к ревью | Парящий свиток |

События старше трёх суток рисуются тусклее. Под картой хроника показывает последние двенадцать; каждая запись выбирает свою провинцию или башню и ведёт на GitHub. Токен остаётся в сборке: на странице нет токена, имён авторов и текстов комментариев, только тип, время, однострочный заголовок, номер PR и ссылка внутри этого репозитория, а сама страница не делает запросов. Файл событий очищается ещё раз при сборке страницы, а упавший или ограниченный по лимиту вызов API означает лишь меньше событий: карта собирается без них, сборка печатает предупреждение. Workflow также запускается каждый час, чтобы активность не устаревала.

## Проверки и локальная сборка

```sh
python scripts/roadmap_map.py            # пишет outputs/roadmap/index.html и outputs/roadmap/world/index.html
python scripts/roadmap_map.py --check    # только проверка
python scripts/roadmap_events.py --repo owner/name --out events.json   # по желанию: активность GitHub (с GITHUB_TOKEN лимит выше)
python scripts/roadmap_map.py --events events.json --repo owner/name   # сборка с этой активностью
```

Сборка завершается ошибкой, если в английской и русской таблицах разные задачи или состояния либо у задачи неподдерживаемый статус или оценка. Оценки задаются в днях (`d`/`д`) или неделях (`w`/`н`), можно указать диапазон. Для дробных чисел используйте точку в английской версии и запятую в русской.

Для непустой правки только статусных ячеек существующих задач в двух точных файлах карты `ModuleEngine CI` запускает `Roadmap status checks`. Задание сверяет обе таблицы, запускает тесты генератора и его модели в Node, проверяет вход без записи файлов и собирает обе страницы. Для остальных изменений сохраняется обычная матрица ОС с прежним выбором маршрутов. `CI required` требует успеха планировщика и всех обязательных заданий выбранного маршрута. Отдельный workflow Roadmap map сохраняет браузерную регрессию в Chromium и публикацию в GitHub Pages.
