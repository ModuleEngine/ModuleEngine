# Проектирование UI редактора ModuleEngine

[English](../SKILL.md) | [Русский](SKILL.ru.md)

Область — нативный UI ModuleEngine: раскладки, обнаружение состава, графы,
Scene, Assets, иконки и обратная связь. Не применять к игровому HUD/арту,
посторонним приложениям или алгоритмам рендера; наблюдаемой регрессии также
нужен moduleengine-debug.

Использовать для взаимодействия/дизайна редактора ModuleEngine, включая явно
разрешённую реализацию. Это не разрешение реализовывать обсуждение, сбрасывать
раскладку, добавлять подсистему/зависимость или что-либо публиковать. Текущий
запрос пользователя приоритетнее базы; осознанное исключение записывается,
а не используется как повод отклонить разрешённое изменение.

## Определить объём и правила

Найти корень ModuleEngine по текущему workspace, проверить AGENTS.md,
docs/current-status.md и исходники редактора. Пути ниже относительны репозиторию,
а не установленному навыку. Если репозиторий недоступен, опираться на переданные
материалы и указать ограничение; спрашивать расположение только при необходимости.
Не искать замену checkout в посторонних личных папках.

Прочитать AGENTS.md, docs/editor-ui-design.md и затронутые разделы
docs/editor-ui-spec.md; для размеров загрузить docs/editor-ui-tokens.json.
В docs/editor-clarity-plan.md отличить выполненное от отложенного. Контракт
runtime/сохранения/прав читать там, где от него зависит часть задачи. Не загружать
весь архив документации.

При реализации установить начальный diff, сохранить авторский JSON, ресурсы,
личные раскладки и постороннюю работу. Зафиксировать задачу, ожидаемое поведение,
область вида/данных, исключения из объёма и конкретный маршрут приёмки. Анализ
или дизайн-документ остаются в своём режиме: редактор не патчится.

## Спроектировать полезное взаимодействие

До переделки проследить настоящее действие. Разделить идентичность проекта,
раскладку, смыслового владельца, область графа и права. Вкладки Engine/Project —
раскладки одного документа. Доступ определяют Full/Team/исходники; Gameplay не
разблокирует замороженное расписание Team. Технические механизмы, переиспользуемый
игровой слой и содержимое игры отделены. Неизвестные данные об активности не
означают ни активность, ни неактивность.

Обнаружение состава начинается с Engine Overview. Специализированные графы —
для настоящих процессов, действия нод фильтруются реальным реестром/областью/
правами. Справка пина объясняет настоящие данные/ограничения у соединения,
не заменяет валидацию словом «текстура» или постоянной легендой жаргона.

Использовать общие размеры/цвета/иконки. Стандартные Play/Pause/Stop/Save и
инструменты Scene имеют узнаваемые векторы, семантические имена, checked/disabled
и справку при наведении/фокусе с настоящими клавишами/причинами. Названия модулей,
неоднозначные/разрушительные команды сохраняют текст. Overlays Scene поглощают
свой ввод, не крадут начатый жест и не выбирают сцену насквозь. Адаптивное меню
переполнения предпочтительнее мелких шрифтов и обрезанных важных команд.

В egui содержимое popup/подменю — отдельная Area: явно передавать состояние
enabled/разрешение редактирования вызывающего UI через каждый уровень меню.
Числовым настройкам нужен `CloseOnClickOutside`, чтобы щелчок для ввода текста
не закрывал меню. Проверять уже открытое меню после входа в Play/отключения
вызывающего UI, а также ввод чисел текстом наряду с перетаскиванием.

Не вызывать другие проверки Context/слоёв/владельца ввода внутри замыканий
egui input/memory/data: вложенный доступ может вызвать deadlock. Сначала
скопировать нужные скаляры или небольшие относящиеся к делу события, освободить
guard, затем проверять владельца. Проверять нажатие/колесо/отпускание одним
пакетом в порядке событий и сохранение владельца при пересечении другой Scene.

Сохранить жесты графа: СКМ/ПКМ двигают вид, щелчок ПКМ по фону добавляет/ищет,
по ноде — открывает действия, колесо без Ctrl масштабирует под указателем,
Alt+ЛКМ удаляет связь, смешанный Delete — один Undo с очисткой. Сначала ввод
принадлежит тексту/popup/границе. Не переносить чужие клавиши и Alt-click по пину.
Это согласованное целевое управление, а не описание текущего UI. Применять его
при реализации ввода графа в объёме задачи; в других частях сохранять незатронутые
привязки, не переводить весь интерфейс на новые правила молча.

Различать dirty/saved/applied/ready/failed и настоящие длительные операции.
Нет вымышленного процента, неработающей Cancel и молчаливой замены рабочей
версии. Навигация раскладок, выбор, движение/масштаб графа не компилируют и не
пересобирают проект. Открытие инструментов не включает отсутствующие модули.

## Проверить и сопровождать

Реализовывать только разрешённую часть через существующие команды/валидацию.
Отделять предложения дизайна от текущего поведения. Визуальные правки сохраняют
точный JSON, стабильные ID, неизвестные данные, разделение авторских/Play-данных
и защиту раскладок/файлов. Новым правилам move/duplicate окна или ввода адреса
нужно явное решение, если задача/контракты их ещё не определили.

Проверки выбирать по изменению: ссылки/согласованность для документации/навыков;
реальные команды, конфликты ввода, error/Cancel, Undo/Save/reopen/права для
поведения. Осмотреть узкие области/DPI, при затрагивании производительности
сравнить одинаковую нагрузку. Статические картинки не подтверждают команды,
сохранение, API доступности или FPS Player. Computer Use применять короткими
сеансами только при необходимости и с навыком гигиены; не оставлять открытым
на время кода/документации.

При изменении базы обновить полные EN/RU-документы и токены. Существенным
изменениям нужен независимый проверяющий по docs/review.md; применение навыка
не делает самопроверку автора независимой. В отчёте: что изменилось, настоящие
проверки, предложения/открытые решения и непроверенные условия.
