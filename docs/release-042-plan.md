## A. Player image

1. **Reproduce an ordinary launch.** Fix the camera, lighting and settings in one scene. Record the DPI, physical game area, rendered frame size and presentation method for the default window, a 1920×1080 window and a different aspect ratio. The verified 0.4.1 Player requested 1920×1080 even for the initial 1280×720 logical point window and stretched the result to the game area. The previous 960×540 captures and the 1920×1080 window test answer different questions. Editor Game and Scene have their own 1280×720 cap. [Player](../crates/player/src/ui.rs) · [Game](../crates/editor/src/game_ui.rs) · [Scene](../crates/editor/src/scene_view_ui.rs)
2. **Check one-to-one presentation.** In the normal Player mode, match the render size to the physical game area at startup and after resize or DPI changes. Following the owner's Scene screenshot and clarification on 16 November, Scene and a single Game pane also default to 100% of their physical viewport pixels, without the former 1280×720 preview cap. A control to reduce render scale remains future work. Check proportions using a circle or square. If a game explicitly fixes its aspect ratio, preserve it and compare the frame against the image area inside the window. Check minimization and rapid resizing. Measure the cost of the change; simultaneous differently shaped Game panes share a Play frame and need separate evidence rather than an assumed per-pane 1:1 claim.
3. **Separate the filter from display scaling.** At 1:1, capture the same high-contrast diagonal and thin detail with Off and FXAA. Record the same camera motion and several frames after it stops. Assess jagged edges, lost detail, a bright fringe on a stationary edge and a trail behind a moving object separately. The shader samples the current frame and blends before sRGB encoding. Test the blending-space hypothesis with a control variant on identical input. Choose a filter change based on frame comparisons and cost. The cause of the reported motion trail remains open. [Shader](../assets/gpu/fxaa.hlsl) · [Render graph](../crates/render-vulkan/src/graph.rs)
4. **Verify the delivery as a player.** Give the owner one runnable Player, its in-game Off/FXAA selector, original-size frames and a short motion recording. The shape keeps its proportions at the new window size and the choice survives a restart. Record reproduced artifacts, improvements, frame-time cost and outstanding checks.

## B. Project Settings and editor windows

1. **Move the primary entry to Edit → Project Settings.** Reuse the existing open command. Verify Full and Team, keyboard access and refocusing an already detached pane with its state intact. Preserve the alternate Windows → Authoring route. [Command](../crates/editor/src/editor_workflow.rs) · [Navigation](../crates/editor/src/window_navigation.rs)
2. **Let a pane follow the pointer.** Press the left mouse button on the free part of its top header or tab. Once the drag threshold is crossed, pull the pane outside into a separate native window, retaining pointer capture across the boundary. On re-entry, preview the destination area and side. The same held button drives the gesture until release. Dropping outside a target leaves the window floating. Escape before placement restores the original layout. Preserve the existing detach and return commands. [Docking](../crates/editor/src/dock.rs) · [Native windows](../crates/editor/src/native_windows.rs)
3. **Verify with real windows.** Tear off Project Settings and leave it floating. On a second drag, dock it next to a chosen area. Repeat the entire out-and-back trip with one hold and check Escape. Pane state, drafts, shared Undo and focus follow the pane. Check the layout after restarting, header menu clicks, the resize divider and the graph under the pointer. Exercise moves between monitors with different DPI when the hardware is available and record the actual coverage.

## Game UI scope

A native game module can register an egui presentation. Custom Rust supplies a panel, text and a choice bound by stable setting ID. Use the existing binding and saved player preference as compatibility checks. Buttons, sliders, visual themes and a UI editor remain future planning topics for a concrete game menu that needs more than the current API provides.
